The run bar The interaction model the whole GUI is built around: nothing is written until you have seen the diff.
Run
Loads the models, computes the proposals, writes report.json. Touches no caption.
the diff
The report read back as before/after rows. Dots the sidebar; fills the caption panel. Warn-toned — it is not on disk.
Apply
Replays that exact report — no model loads — so it can only write what the diff showed. Disabled until a Run produced one.

Rules the bar encodes
→Exactly one .primary — the button that writes. Greyed until allowed, never moved.
→Run is this image; Run batch is the Settings pattern.
→A disabled button keeps its tooltip — hovering says why.
→Red never appears in the bar — only in the confirm dialog, next to a count.
One button, two jobs
Undo idle Cancel running
The same slot: nothing to undo while something runs, and a long pass must stay stoppable. Undo restores the apply report's before-text, skipping any caption edited since.
The dock is the only thing that runs Python — but not the only thing that writes. A caption you retype goes straight to disk on Save. Your edits are immediate; it is the machine's that must be shown first.
