# anime_tools 가이드북

이 문서는 **anime_tools**로 데이터셋을 큐레이션하는 과정을 처음부터 끝까지 안내하는 가이드입니다:
설치하고, 이미지를 제자리에 두고, 웹 GUI를 열고, 캡션 / 그룹화 / 마스크 스테이지를 순서대로
실행한 뒤, 결과를 [Anima LoRA 트레이너](https://github.com/sorryhyun/anima_lora)에 넘깁니다.
한 줄 설치 프로그램으로 설치했고 코드를 열어 본 적이 없는 분을 위해 썼습니다.
각 스테이지가 무엇을 읽고 쓰는지, 그리고 실행을 어떻게 되돌리는지를 설명합니다;
노브 자체는 각 스테이지의 `--help`에서 생성된 폼에 있으며, 각 절에서 링크한 설계 문서가 그것들을
설명합니다.

## 1. 이 도구는 무엇인가요

`anime_tools`는 Anima LoRA 트레이너의 데이터셋 큐레이션 절반을 단독으로 돌 수 있도록 떼어낸
것입니다: 설치가 더 작고, DiT도 VAE도 없으며, 만들어 낸 데이터셋은 어떤 트레이너에든 넘길 수
있습니다. 손으로 쓴 캡션이 붙은 이미지 폴더를 받아, 트레이너가 학습 전에 읽는 모든 것 —
버킷 리사이즈된 이미지, 교정되고 보강된 캡션, 캡션 변형, 유형이 지정된 태그 인덱스, 학습 마스크,
중복을 솎아내기 위한 그룹화 매니페스트 — 을 만들어 냅니다.

트레이너는 이 패키지에 의존하며; 이 패키지는 절대 트레이너를 임포트하지 않습니다.
둘이 합의하는 모든 것 — 파일 이름, 캡션 문법, 무엇이 어디에 놓이는지 — 은
[`docs/contract.md`](../contract.md)에 한 번만 적혀 있습니다.

## 2. 시스템 요구사항

| 항목 | 비고 |
|---|---|
| Python | **3.13**. 설치 프로그램이 이 버전을 고정하며, 머신에 없으면 `uv`가 받아옵니다. |
| GPU | 선택 사항이지만 강력히 권장합니다. 모든 모델 스테이지(태거, SAM3, PE-Spatial, 텍스트 세그멘터, OCR)는 CPU에서도 돌아가지만, 속도는 몇 분의 일 수준입니다. 각 스테이지는 torch가 CUDA를 인식하면 CUDA를, 아니면 CPU를 고릅니다. |
| 운영체제 | Linux, Windows, macOS. macOS에는 CUDA도 triton도 없습니다; 패키지가 SAM3에 둘을 우회하는 심(shim)을 넣어 두었으므로, SAM3 스테이지는 거기서 CPU로 돌아갑니다. |
| 디스크 | 스테이지가 첫 사용 시 받아오는 모델(태거 백본, SAM3, PE-Spatial, 텍스트 넷, OCR, Danbooru 태그 KB)과 `workspace/` 아래의 데이터셋 리사이즈 사본. |

> **PyPI의 Windows torch는 CPU 전용입니다.** 그래서 PowerShell 설치 프로그램은 기본값으로
> CUDA 13.0 torch 인덱스를 씁니다(§3). PyPI의 Linux torch는 이미 CUDA를 번들합니다.

## 3. 설치

### 3.1 한 줄 설치 (체크아웃 불필요)

Linux / macOS:

```bash
curl -fsSL https://github.com/sorryhyun/anime_tools/releases/latest/download/install.sh | sh
```

Windows (PowerShell):

```powershell
irm https://github.com/sorryhyun/anime_tools/releases/latest/download/install.ps1 | iex
```

둘 다 [uv](https://astral.sh/uv)가 없으면 설치한 다음, 최신 릴리스를 torch와 SAM3까지 포함해
자체 가상 환경에 `uv tool install`하고, `anime-tools-gui`를 PATH에 올립니다.
git 체크아웃도 CUDA 툴킷도 필요 없습니다: torch 휠이 CUDA 런타임을 함께 담고 있습니다.

설치 프로그램을 조정하는 환경 변수는 두 가지입니다:

| 변수 | 효과 |
|---|---|
| `ANIME_TOOLS_VERSION=v0.3.1` | 최신 릴리스 대신 해당 태그를 설치합니다. |
| `TORCH_INDEX=https://download.pytorch.org/whl/cu130` | torch용 추가 패키지 인덱스. PowerShell 설치 프로그램은 이미 이 값을 기본으로 씁니다; Linux에서는 CPU 전용 빌드(`…/whl/cpu`)에만 필요합니다. |

설치가 끝나면 PATH 변경이 반영되도록 **새 셸**을 열고 나서:

```bash
cd <your dataset folder>
anime-tools-gui --open
```

### 3.2 내 프로젝트의 의존성으로 설치

```bash
uv add "anime-tools @ git+https://github.com/sorryhyun/anime_tools"
```

PyPI 패키지는 없습니다; 태그를 고정하거나 `[tool.uv.sources]`를 체크아웃으로 가리키세요.
자신의 `pyproject.toml`에 복사해 넣어야 할 것이 하나 있습니다: SAM3는 `numpy<2`를 고정하는데,
그 고정은 낡았습니다. 이 저장소는 그것을 오버라이드하지만, uv는 워크스페이스 루트에서만
`[tool.uv]`를 존중하므로, anime-tools에 *의존하는* 프로젝트는 오버라이드를 반복해야 하고
그러지 않으면 numpy에서 해결(resolve)이 실패합니다:

```toml
[tool.uv]
override-dependencies = ["numpy>=2.0"]
```

위의 설치 프로그램들은 같은 오버라이드를 명령줄로 넘깁니다.

### 3.3 tool 설치 환경에서 CLI 실행하기

PATH에 있는 명령은 `anime-tools-gui` 하나뿐입니다. 터미널에서 스테이지를 실행하려면 도구의 환경
안에서 Python을 실행하세요:

```bash
uv tool run --from anime-tools python -m anime_tools.downloads --list
```

## 4. 큐레이션 홈과 그 구조

모든 것은 하나의 디렉터리, 즉 **큐레이션 홈**을 기준으로 합니다. 우선순위 순으로
`ANIME_TOOLS_HOME`, 그다음 `ANIMA_HOME`(트레이너 자체의 홈이므로, 트레이너가 쓰는 트리가
그대로 동작합니다), 그다음 실행한 디렉터리입니다. `anime-tools-gui --home <dir>`는 그 서버의 홈을
지정합니다.

```
<home>/
  image_dataset/                  INPUT  — your images + hand-written captions; the tools only read it
  workspace/                      everything the tools produce
    resized/<rel>.png               bucket-resized image — the tree every stage reads
    resized/<rel>.txt               the revised caption (stage output)
    resized/<rel>.history.txt       what that caption used to say, one line per version
    resized/<rel>.variants.txt      shuffle / dropout variants, v0 = pristine
    ocr/<rel>.ocr.txt               words in the picture (OCR); not a caption
    masks_sam/  masks_mit/          each mask generator's own tree
    masks/<rel>/{stem}_mask.png     the merge of the two — what Export publishes
    captions/<stage>/report.json    what each run did, and how to undo it
    groups/groups.json              the grouping manifest
  post_image_dataset/             OUTPUT — written only by Export; the tree the trainer reads
  models/                         model weights (ANIME_TOOLS_MODELS overrides)
```

앞으로 보게 될 것 대부분은 세 가지 규칙으로 설명됩니다:

- **`image_dataset/`는 스테이지에게 읽기 전용입니다.** 거기 있는 캡션이 *마스터(master)*입니다.
  모든 스테이지는 대신 `workspace/resized/` 아래에 *수정본(revised)* 캡션을 쓰며, 수정본 캡션이
  아직 없으면 마스터로 대체합니다. 마스터를 쓰는 것은 단 둘뿐입니다: 그 단(rung)을 손으로 편집할
  때의 GUI 캡션 편집기, 그리고 Export입니다.
- **이미지를 여는 모든 스테이지는 `workspace/resized/` 아래에서 엽니다** — 마스킹과 그룹화도
  포함이므로, 파이프라인 전체가 하나의 기하를 공유합니다. `image_dataset/`에만 있는 이미지는
  그들에게 보이지 않습니다. GUI가 Resize를 필요로 하는 모든 스테이지 앞에서 자동으로 실행하는
  이유입니다(§7.1).
- **Export 말고는 아무것도 `workspace/` 밖에 쓰지 않습니다**(§7.9). 워크스페이스를 지우고 다시
  만들 수 있으며; 스테이지 때문에 마스터 캡션을 잃는 일은 없습니다.

이미지 파일은 스템(stem)으로 캡션과 짝지어집니다: `chars/alice/001.png`는 `chars/alice/001.txt`를
읽습니다. 하위 폴더는 파이프라인 전체에서 그대로 유지됩니다(위의 `<rel>`).

> **워크스페이스 이전 설치에서 업그레이드하기**(`post_image_dataset/resized/`에 직접 쓰던
> 설치): `python -m anime_tools.workspace.migrate`는 무엇을 옮길지 출력하고, `--apply`가
> 실제로 옮깁니다. 디렉터리 이름을 바꿀 뿐 절대 병합하지 않습니다: 이미 있는 목적지는 보고하고
> 건너뜁니다. ⚙ Settings에서 옛 경로로 고정해 둔 데이터셋 루트는 이름만 알려주고 다시 쓰지
> 않습니다 — 거기서 직접 지우세요.

## 5. Hugging Face 로그인과 모델

모델 중 두 개는 Hugging Face Hub에서 **게이티드(gated)**입니다: dbv4 태거 백본(GPL-3.0, 절대
동봉하지 않으며 — 로드 시 *여러분의* 토큰으로 받아옵니다)과 SAM 3입니다. 둘 다 read 권한이 있는
토큰이 필요하고, 그 토큰의 계정이 각 저장소의 약관에 한 번은 동의해 두어야 합니다.

GUI에서: ☰ → **⚙ Settings…** → *Hugging Face* → 토큰을 붙여넣습니다. 토큰은
`huggingface_hub`의 로그인에 넘겨져 거기에 저장되며, 다시 표시되지 않습니다. 토큰이 설정될
때까지 헤더에 **⚠ no HF token**이 표시됩니다. Models 목록의 게이티드 행에는 *accept the terms*
링크가 있습니다; 같은 계정으로 로그인한 상태에서 여세요.

미리 받아 둘 것은 없습니다: **모든 스테이지는 첫 사용 시 필요한 것을 받아옵니다.**
**Models & weights** 대화상자(☰ → *Models & weights*)는 체크포인트마다 한 행씩 — 용도, 설치
여부, 저장 위치 — 나열하며, 행마다 **Download** 버튼이 있고 **Download all N missing** 버튼도
있습니다. 다운로드는 보통의 작업으로, 한 번에 하나씩, 스테이지와 슬롯을 공유하며 실행됩니다.
이 버튼들은 기다림과 게이티드 저장소 거부를 여러분이 고른 시점으로 옮겨 줄 뿐입니다.

터미널에서:

```bash
python -m anime_tools.downloads --list        # every row: installed / MISSING, repo, destination
python -m anime_tools.downloads               # fetch every missing one
python -m anime_tools.downloads sam3 tagger   # fetch by id
```

가중치는 `<home>/models/` 아래에 놓입니다(`ANIME_TOOLS_MODELS`로 변경). 예외는 SAM3 피사체
소프트 프롬프트로, 트레이너가 그것을 두는 곳이 `networks/calibration/`이기 때문에 거기에
있습니다.

## 6. GUI

```bash
anime-tools-gui --open              # http://127.0.0.1:8790, opens the browser
anime-tools-gui --home ~/datasets/x # a different curation home
anime-tools-gui --host 0.0.0.0      # expose on the LAN (a headless GPU box)
```

포트가 사용 중이면 다음 빈 포트를 쓰고 그 번호를 출력합니다. `--host 0.0.0.0`에는 **인증이
없습니다** — 앞에 자체 터널을 두세요. 서버 자체는 모델을 절대 로드하지 않습니다: 모든 스테이지는
`python -m …` 서브프로세스로 한 번에 하나씩 실행되며, 그 출력이 패널로 스트리밍됩니다.

### 6.1 사이드바가 곧 데이터셋입니다

`image_dataset/` 아래의 모든 이미지가 폴더 구조 그대로 나열되고, 행마다 무엇이 있는지를 점으로
표시합니다: 리사이즈됨, 마스크 있음, 그리고 캡션 단(rung)마다 점 하나. 각 이미지 아래에서
캡션들은 오래된 것부터 **사다리(ladder)**를 이룹니다:

| 단 | 파일 | 편집 가능 |
|---|---|---|
| **master** | `image_dataset/<rel>.txt` — 손으로 쓴 것; 스테이지는 읽기만 합니다 | 예 |
| **history** (`revised@1`, `revised@2`, …) | `<rel>.history.txt` — 수정본 캡션이 예전에 담고 있던 내용, 그것을 교체한 각 실행 이전의 것 | 아니요 |
| **revised** | `workspace/resized/<rel>.txt` — 스테이지 출력; 다음 실행이 이것을 다시 쓰면서 이 텍스트를 한 버전으로 보관합니다 | 예 |
| **variants** (`v0`, `v1`, …) | `<rel>.variants.txt` — 생성된 것; `v0`가 원형 그대로의 수정본 캡션입니다 | 아니요 |

**filter** 상자는 트리를 좁히고; `↑`/`↓` 또는 `j`/`k`로 이미지 사이를 오가며; URL의
`#<rel>|<kind>`는 캡션 하나로 가는 링크입니다. **tree / groups** 토글은 같은 목록을 두 가지
순서로 그립니다 — 폴더 순서, 또는 Groups 스테이지가 찾은 근사 중복(near-twin) 그룹
순서(§7.7)입니다.

### 6.2 캡션 편집기

이미지를 선택하면 캡션 옆에 그 이미지(원본 / 마스크 / 오버레이)를 보여주며, 편집기는 하나이고
버전마다 배지가 붙습니다. 태그 묶음과 각 위치 절은 텍스트 안에서 상자로 표시되는데; 상자는
서버 자체 파서에서 오므로, 브라우저가 캡션 구조를 추측하는 일은 없습니다.
태그를 더블클릭하면 Danbooru 태그 KB에서 찾아봅니다(다운로드된 뒤부터).

**Save**(⌘/Ctrl+Enter)는 `master` 또는 `revised`를 씁니다; 다른 단은 읽기 전용입니다.
모든 쓰기는 손으로 했든 스테이지가 했든 똑같이, 교체된 텍스트를 히스토리 단에 올립니다.
저장하면 다음에 할 일을 알려줍니다: 트레이너의 텍스트 인코더 재인코딩은 항상, 그리고 이미
`.variants.txt`가 있던 수정본 캡션을 편집했다면 *Correct 재실행*도 — 그 사이드카가 이제 낡았기
때문입니다.

캡션 아래에는, OCR 스테이지가 읽은 이미지라면 **text in the image**(이미지 속 텍스트)가 각 줄의
신뢰도와 위치와 함께 표시됩니다(§7.6).

### 6.3 독(dock)이 곧 스테이지 실행기입니다

하단을 따라 늘어선 버튼 줄이 **곧 스테이지 목록입니다**: Resize는 뒤에 숨어 있고, 버튼은
**Autotag · Curate · OCR · Groups · Masks · Export**입니다. Curate는 세 스테이지(Position /
Correct / Audit)를, Masks도 세 스테이지(Subject / Text / Merge)를 품고 있으며, 패널 안에서
고릅니다. 한 번 클릭하면 스테이지의 폼이 열리고; 열린 것을 다시 클릭하면 독이 접힙니다.

폼은 스테이지 자체의 `--help`에서 생성됩니다. 실행마다 바꿔 볼 만한 노브들을 펼친 채 열리고;
나머지는 각 그룹 하단의 **▸ advanced (n)** 아래에 접혀 있으며, 숨겨진 필드가 기본값에서 벗어나
있으면 표시가 붙습니다. 데이터셋 루트, 리포트 루트, 모델 경로는 폼에 절대 나타나지 않습니다 —
⚙ Settings에서 옵니다.

- **Run**은 선택한 이미지 하나에만 스테이지를 실행합니다(**just `<rel>`**).
- **Run batch**는 Settings의 `path_pattern`이 가리키는 모든 이미지에 실행합니다 — `*`는 데이터셋
  전체입니다.
- **Undo**는 이 스테이지의 마지막 실행이 쓴 것을, 그 리포트를 거꾸로 재생해 되돌립니다.
- **Cancel**은 실행 중인 작업을 멈춥니다.

패널을 한국어로 두면 이 버튼들은 **실행 / 일괄 실행 / 되돌리기 / 중단**으로, ☰ 메뉴의 항목은
**⚙ 설정… / 모델과 가중치 / 언어**로 표시됩니다. 이 문서는 영어 이름을 그대로 씁니다.

**Run은 실제로 씁니다.** GUI에는 Apply 게이트가 없습니다: 실행이 교체한 것은 캡션의 버전
배지(`revised@2`)가 되고, 실행의 리포트는 캡션 패널에서 이미지별 diff로 다시 읽히며, Undo는 그
리포트를 두 텍스트를 맞바꿔 재생한 것입니다. Undo에는 보호 장치가 있습니다: 실행 후 손으로
편집한 캡션은 그대로 두고 건너뛴 것으로 셉니다.

가장 최근 출력 줄은 스테이지 바에 표시되고; **log** 버튼이 전체를 엽니다. 이미지를 순회하는
스테이지는 진행 표시줄을 보여주고; 앞에 프리플라이트(preflight)가 붙은 실행은 먼저
*step 1/2 · resize*를 보여줍니다.

### 6.4 ⚙ Settings는 세 개의 대화상자입니다

| 대화상자 | 담는 것 |
|---|---|
| **Settings** | 큐레이션 홈과 모델 디렉터리, 다섯 개의 **데이터셋 루트**(`src`, `master`, `dst`, `masks`, `out`), Hugging Face 토큰. |
| **Advanced settings** | 해당 값을 받는 모든 스테이지에 채워지는 **스테이지 기본값**(`path_pattern`, 태거 디렉터리, SAM3 체크포인트와 소프트 프롬프트, 리포트 루트, 마스크 루트), 그리고 **Preprocess** 블록 — Resize에는 독 버튼이 없으므로, 여기가 Resize 스테이지 자체의 폼입니다. |
| **Models & weights** | §5의 모델 행들. |

각 대화상자는 자신이 담은 것만 저장합니다. 루트는 큐레이션 홈 기준 상대 경로이며; 없는 루트는
표시됩니다. 패널은 저장된 설정이 가리키는 어떤 루트든 *읽을* 수 있지만, 디렉터리를 *만드는*
것은 홈 아래에서만 하므로, 외부 루트의 오타는 새 빈 디렉터리가 아니라 없는 루트가 됩니다.

☰ 메뉴의 **Language** 행은 패널을 영어, 한국어, 일본어, 중국어 사이에서 그 자리에서
전환합니다; 첫 방문에는 브라우저 자체의 언어 목록을 따릅니다. 번역되는 것은 패널의 크롬뿐입니다
— 스테이지의 제목, 폼 라벨과 도움말은 그 `--help`에서 오므로 영어 그대로이고, 캡션, 태그,
경로는 데이터입니다.

## 7. 스테이지별 워크플로우

위에서 아래로 실행하세요. 각 스테이지는 리사이즈된 트리를 읽으므로 이미지는 Resize를 한 번만
거치고, 각 캡션 스테이지는 이전 스테이지가 쓴 수정본 캡션을 읽습니다.

### 7.1 Resize (자동)

**읽기**: `image_dataset/`. **쓰기**: `workspace/resized/<rel>.png`.

모든 이미지는 자신을 가장 적게 리사이즈하는 버킷 티어에 들어가며, 그 티어의 토큰 밴드 안에서
원래 종횡비를 유지합니다. 기하는 트레이너 자체의 것이므로, 어느 쪽이 먼저 리사이즈하든 다른
쪽은 모든 이미지가 이미 버킷에 맞는 것을 보고 건너뜁니다. 픽셀 하한(기본 0.5 MP) 미만의
이미지는 리포트에서 **건너뛰고 이름을 밝힙니다** — 그런 이미지는 절대 리사이즈되지 않으므로
어떤 스테이지도 보지 못합니다; 이미지 패널의 픽셀 수 칩이 그 사실을 알려주며, 하한은
⚙ Advanced settings › Preprocess에 있습니다.

직접 클릭할 일은 없습니다: GUI가 리사이즈된 트리를 읽는 모든 스테이지의 첫 단계로 실행하며,
이미지 한 장에 대한 실행은 그 이미지만 리사이즈합니다. 이미 최신인 이미지는 건너뛰므로
프리플라이트는 거의 공짜입니다. 항상 씁니다; 드라이 런(dry run)은 없습니다.

> 티어(`target_res`)는 트레이너의 것과 일치해야 합니다. 그렇지 않으면 서로 상대의 출력을 계속
> 다시 리사이즈합니다.

### 7.2 캡션 자동 태깅 (Autotag)

**읽기**: 리사이즈된 각 이미지와 그 캡션(수정본, 없으면 마스터). **쓰기**: 수정본 캡션.
**모델**: Anima Tagger(태거 체크포인트 + 게이티드 dbv4 백본).

이미지마다 Anima 순서의 태그 문자열 — `rating, count, characters, copyrights, @artists,
generals` — 을 예측합니다. 모드는 세 가지입니다:

| 모드 | 하는 일 |
|---|---|
| `missing` (기본) | **어떤 캡션도 말해 주지 않는** 이미지만. 기존 것은 건드리지 않습니다. |
| `merge` | 캡션에 없는 태그를 덧붙이며, 위치 절은 유지합니다. |
| `overwrite` | 캡션을 통째로 교체합니다. 옛 텍스트는 히스토리 버전으로 보관됩니다. |

비파괴적인 것은 `missing`뿐이며; 나머지 둘은 히스토리 단과 Undo로 되돌릴 수 있습니다.
출력은 출발점으로 여기세요 — 학습 전에 이름, 시리즈, 아티스트를 확인하세요.
태거 자체는 [`docs/anima_tagger.md`](../anima_tagger.md)를 보세요.

### 7.3 캡션 교정 + 미러링 (Correct)

**읽기**: 마스터 캡션과 Danbooru 태그 KB. **쓰기**: 수정본 캡션과, 선택적으로
`.variants.txt`.

각 마스터를 교정된 수정본 캡션으로 미러링합니다: KB에 맞춰 태그 유형을 정하고 Anima의 버킷
순서로 정렬하며, 선택적으로 트리거 워드를 끼워 넣고, 선택적으로 `@no-artist` 센티널을 넣고,
선택적인 **드롭 그룹(drop groups)**으로 마스터는 건드리지 않은 채 미러링된 모든 캡션에서 태그
계열 전체를 제거합니다. 변형 개수를 설정하면 `<rel>.variants.txt`도 씁니다: `v0`는 교정된
캡션이고, `v1…`은 트레이너가 그대로 인코딩하는 스마트 셔플과 드롭아웃 추출본입니다.

항상 씁니다; 드라이 런도 리포트도 없으므로 Undo도 없습니다 — 교체된 텍스트는 히스토리 단에
있습니다. KB는 Models(§5)의 **Danbooru tag KB** 행이며; 그 선택적인 English 행은 태그 조회가
보여주는 설명을 다시 씁니다.

> Correct는 **마스터**를 미러링합니다. 수정본 캡션의 위치 절은 재실행에도 살아남지만(새 미러에
> 다시 붙습니다), Autotag `merge`가 평면 태그 묶음에 추가한 태그는 살아남지 못하므로, Correct를
> Autotag `merge` 뒤가 아니라 앞에 실행하세요.

### 7.4 위치 캡션 (Position)

**읽기**: 리사이즈된 이미지와 그 캡션. **쓰기**: 수정본 캡션. **모델**: SAM 3(게이티드),
피사체 소프트 프롬프트, Anima Tagger.

피사체가 둘 이상인 이미지에 대해, 각 피사체를 검출하고, 읽기 순서로 정렬하고, 각각을 마스크로
지운 크롭에 태그를 단 뒤, 캡션을 위치 절 문법으로 다시 씁니다:
`<flat tag bag>. On the left, …. On the right, ….` 한 피사체에 속하는 태그는 평면 태그 묶음에서
그 피사체의 절로 *이동*하며; 큐레이션된 캡션이 한 번도 말하지 않은 것은 작은 허용치를 넘어서는
지어내지 않습니다. 피사체가 하나인 이미지는 건너뛰고 리포트에 그 이유를 적습니다.

적용은 다시 쓴 캡션 옆의 낡은 `.variants.txt`를 모두 삭제합니다. **되돌리기**는 자체 모드인
`--flatten`으로, 모델을 로드하지 않고 모든 절을 평면 태그 묶음으로 다시 합칩니다 — 또는
Undo입니다. 전체 문법, 게이트, 모든 노브는
[`docs/position_captions.md`](../position_captions.md)에 있습니다.

### 7.5 멀티뷰 감사 (Audit)

**읽기**: 위치 스테이지가 건너뛴 단일 피사체 이미지. **쓰기**: **마스터 캡션**에
`multiple views`를, 그리고 그것만. **모델**: Position과 같음.

실제로는 한 소녀의 여러 뷰인 `1girl` 이미지를 찾아, 각각을 리포트 디렉터리 아래의 컨택트
시트와 함께 보고합니다. 적용은 기본적으로 강한 판정에만 게이트되어 있으며; 약한 판정은 기하만을
근거로 하므로 먼저 그 시트를 검토하세요.

> `image_dataset/`에 직접 쓰는 유일한 스테이지입니다. 리포트가 모든 쓰기의 이전 텍스트를 담고
> 있으며, Undo가 그것을 읽어 되돌립니다.
> [`docs/multiview_audit.md`](../multiview_audit.md)를 보세요.

### 7.6 OCR 텍스트

**읽기**: 리사이즈된 이미지. **쓰기**: `workspace/ocr/<rel>.ocr.txt`. **모델**: PP-OCRv6
검출 + 인식(영어, 중국어, 일본어; 한글 없음).

*그림 안의* 글자 — 대사, 간판, 효과음 — 를 신뢰도와 위치와 함께 한 줄에 하나씩 기록합니다.
이것은 **캡션이 아닙니다**: 다운스트림에서 아무것도 이것을 인코딩하지 않고, 캡션을 읽거나 쓰지
않으며, 이후에 재인코딩도 필요 없습니다. 이미지 패널이 그 줄들을 보여줍니다.
기본적으로 ASCII만으로 된 줄(페이지 번호, URL)은 버리고, 세로쓰기 일본어 열은 말풍선당 한 줄로
합칩니다.

### 7.7 그룹 생성 (Groups)

**읽기**: 리사이즈된 이미지. **쓰기**: `workspace/groups/groups.json`. **모델**: PE-Spatial.

거의 동일한 이미지 — 중복, 대체 버전, 한 그림의 크롭 — 를 최상위 폴더 단위로, 파일 이름이나
캡션이 아니라 시각적 내용으로 클러스터링합니다. 사이드바의 **groups** 정렬이 그 결과를
그립니다: 그룹당 접을 수 있는 헤더 하나씩이므로, 중복이 한자리에 모여 솎아내기 쉽습니다.
필터와 대기 중(pending) 점은 두 정렬 모두에서 같은 의미입니다.

재실행 비용은 낮습니다: 피처는 `~/.cache/near_twin/`(`NEAR_TWIN_CACHE`로 변경) 아래에 캐시되고
파일의 크기와 mtime으로 스탬프되므로, 다시 리사이즈하면 정확히 바뀐 이미지만 다시 계산합니다.
폼의 두 매치 임계값으로 클러스터링 기준을 조이거나 늦추세요. [`docs/grouping.md`](../grouping.md)를
보세요.

### 7.8 마스크: Subject, Text, Merge

**읽기**: 리사이즈된 이미지. **쓰기**: `workspace/masks_sam/`, `workspace/masks_mit/`, 그리고
둘의 병합을 `workspace/masks/` 아래에 — 원본 하위 폴더를 그대로 따르는 8비트 `{stem}_mask.png`.
**모델**: 두 생성기 모두 SAM 3; Text에는 만화 텍스트 세그멘터와 ComicTextDetector 게이트.

- **Subject**는 피사체를 남기고 배경을 마스크 처리합니다: 기본적으로 학습된 피사체 프롬프트로
  SAM3를 그라운딩합니다. 마스크로 *가려 낼* 프롬프트(`speech bubble,text`)를 추가할 수
  있습니다.
- **Text**는 글자와 말풍선을 두 검출기로 마스크 처리하며, 각각 자체 스위치 뒤에 있습니다 —
  프롬프트를 준 SAM3(말풍선은 형태)와 UNet++ 세그멘터(글자는 획) — 하나의 팽창(dilation) 전에
  합집합을 취합니다. 둘 다 끈 것이 이 스테이지가 거부하는 유일한 폼입니다.
- **Merge**는 두 트리의 픽셀 단위 최솟값을 `workspace/masks/`에 넣습니다. 사이드바가 *mask* /
  *overlay*로 보여주고 Export가 발행하는 트리입니다. 입력 트리가 없으면 건너뛰므로, 생성기
  하나만 돌린 것도 유효한 절반입니다.

세 디렉터리는 필드 셋이 아니라 설정 하나입니다. 두 생성기가 마스크 이름을 똑같이 짓기 때문에,
공유 트리에서는 서로 덮어쓰기 때문입니다. 마스크는 항상 쓰며; 하나를 바꾸려면 다시 생성하세요.
[`docs/masking.md`](../masking.md)를 보세요.

### 7.9 워크스페이스 내보내기 (Export)

**읽기**: 워크스페이스. **쓰기**: `post_image_dataset/` — 그리고 수정된 마스터라면
`image_dataset/`.

워크스페이스 밖에 쓰는 유일한 스테이지입니다. 여섯 종류의 산출물 — 리사이즈된 이미지, 수정본
캡션, 변형 사이드카, 마스크, 수정된 마스터, 캡션 인덱스 — 을 발행하며, 각각을 목적지와 대조해
따로 결정합니다: 동일한 파일은 건너뛰므로(텍스트는 바이트 비교, 픽셀은 크기와 mtime), 바뀌지
않은 데이터셋을 다시 내보내는 것은 파일당 순회와 stat 한 번씩입니다. 항상 **복사**하고 절대
링크하지 않으므로, 워크스페이스를 지워도 내보내기 트리는 남습니다.

CLI에서는 기본이 드라이 런이며 무엇을 복사할지 나열합니다. GUI에서 **Run**은 복사하고,
**Undo**는 내보내기 자체의 장부에서 덮어쓴 텍스트를 복원합니다; 덮어쓴 *픽셀*은 복원할 수
없으며 그렇게 보고됩니다. 트레이너는 Export가 쓴 것만 읽습니다 — 모든 경로는
[`docs/contract.md`](../contract.md) §2를 보세요.

---

## 8. 트레이너로 넘기기

1. **Export**(§7.9). 트레이너는 이미지와 수정본 캡션을 `post_image_dataset/resized/`에서,
   마스크를 `post_image_dataset/masks/`에서, 마스터를 `image_dataset/`에서 읽습니다.
2. 트레이너에서, 캡션을 바꾼 적용이 있었다면 그 뒤에 **텍스트 임베딩을 다시 인코딩**하세요 —
   트레이너의 `make preprocess-te`입니다. 트레이너의 캐시는 그대로 재사용되며 스스로 만료되는
   일이 없으므로, 캐시가 옛것인 채로 캡션이 바뀌면 옛 텍스트로 학습합니다.
3. Resize는 공유됩니다: 티어가 일치한다면, 트레이너의 `make preprocess-resize`는 모든 이미지가
   이미 버킷에 맞는 것을 보고 건너뜁니다.

둘 다 같은 홈을 가리키게 하면(여기서는 `ANIMA_HOME`도 존중됩니다) 아무것도 옮길 필요가
없습니다. 거기서부터는 트레이너 자체의 가이드 — [Anima LoRA 가이드북][trainer-guide] — 가
이어받습니다.

[trainer-guide]: https://github.com/sorryhyun/anima_lora/blob/main/docs/guidelines/가이드북.md

## 9. CLI 대응 명령

모든 스테이지는 GUI 폼이 채우는 것과 같은 요청 객체 위의 `python -m` 모듈이며, 폼 필드마다
플래그 하나입니다(`--help`가 나열합니다). 경로는 큐레이션 홈 기준입니다. 캡션 스테이지는
플래그를 밑줄로(`--path_pattern`), 그룹화와 마스킹은 하이픈으로(`--source-dir`) 씁니다; 어느
표기든 어디서나 받아들입니다.

| 스테이지 | 모듈 | `--apply` 없이 쓰나요? |
|---|---|---|
| Resize | `anime_tools.stages.cli.resize_images` | 항상 씀 |
| Autotag | `anime_tools.stages.cli.autotag_captions` | 드라이 런 → `report.json` |
| Position | `anime_tools.stages.cli.position_captions` | 드라이 런 → `report.json` |
| Correct | `anime_tools.stages.cli.correct_captions` | 항상 씀 |
| Audit | `anime_tools.stages.cli.audit_multiview` | 드라이 런 → `report.json` |
| OCR | `anime_tools.stages.cli.ocr_captions` | 드라이 런 → `report.json` |
| Groups | `anime_tools.grouping.cli.build_groups` | 항상 `groups.json`을 씀 |
| Subject 마스크 | `anime_tools.masking.cli.generate_masks` | 항상 씀 |
| Text 마스크 | `anime_tools.masking.cli.generate_masks_mit` | 항상 씀 |
| Merge 마스크 | `anime_tools.masking.cli.merge_masks` | 항상 씀 |
| Export | `anime_tools.stages.cli.export_workspace` | 드라이 런 → `report.json` |

드라이 런 스테이지는 `workspace/captions/<stage>/` 아래에 `report.json`을 쓰고 멈춥니다.
`--apply`는 실제로 씁니다. `--from_report <report.json>`은 모델을 로드하지 않고 드라이 런의
제안을 재생하며, 그 사이에 바뀐 캡션은 건너뛰고, 읽은 리포트 옆에 `apply_report.json`을
씁니다. GUI의 Undo는 같은 재생을 거꾸로 한 것입니다.

```bash
python -m anime_tools.stages.cli.autotag_captions --mode merge            # dry run
python -m anime_tools.stages.cli.autotag_captions --mode merge --apply    # write
python -m anime_tools.stages.cli.export_workspace --apply                 # publish
```

Python API도 같은 객체입니다: [`examples/`](../../examples/README.md)에 기능마다 실행 가능한
스크립트가 하나씩, CLI 옆에 API가 나란히 있습니다.

## 10. 업데이트

```bash
uv tool upgrade anime-tools          # tool install
uv lock --upgrade-package anime-tools   # as a dependency
```

GUI는 커밋된 번들이므로, 업데이트에 프런트엔드 빌드가 필요 없습니다. 스테이지의 폼은 설치된
코드에서 생성되므로, 새 플래그는 저절로 폼에 나타납니다.

## 11. 문제 해결

**스테이지가 게이티드 저장소 오류(Hub의 401 / 403)로 실패합니다.** 토큰이 없거나, 계정이 그
저장소의 약관에 동의하지 않은 것입니다. ⚙ Settings에서 토큰을 설정한 다음, Models & weights의
해당 행에 있는 *accept the terms* 링크를 같은 계정으로 로그인한 상태에서 여세요.
Download 버튼은 스테이지를 전부 돌리지 않고도 그 실패를 재현합니다.

**내 프로젝트에서 `uv`가 numpy 해결에 실패합니다.** SAM3의 낡은 `numpy<2` 고정 때문입니다.
§3.2의 오버라이드를 `pyproject.toml`에 추가하세요.

**macOS: `import sam3`가 triton에 대해 불평하거나, 텐서를 `cuda`에 올릴 수 없습니다.** 둘 다
패키지의 SAM3 로더 안에서 처리됩니다; 이것이 보인다면 sam3를 직접 임포트하고 있거나 옛
릴리스를 실행하고 있는 것입니다. 거기서 SAM3 스테이지는 CPU로, 느리게 돌아갑니다.

**Windows: torch에 CUDA가 없습니다.** PyPI의 Windows torch는 CPU 전용입니다. CUDA 인덱스를
기본으로 쓰는 PowerShell 설치 프로그램으로 다시 설치하거나, `TORCH_INDEX`를 명시적으로
설정하세요.

**스테이지가 이미지를 하나도 못 봅니다 / 이 이미지에 아무것도 하지 않습니다.** 그 이미지가
`workspace/resized/` 아래에 없는 것입니다. 리사이즈 하한 아래에 있거나(픽셀 수 칩이 그렇게
알려줍니다; ⚙ Advanced settings › Preprocess에서 하한을 낮추세요), `src` 루트가 데이터셋을
가리키고 있지 않은 것입니다.

**"saved — .variants.txt is now stale".** 변형이 있던 수정본 캡션을 편집한 것입니다.
같은 변형 개수로 Correct를 다시 실행한 다음, 트레이너의 TE 재인코딩을 하세요.

**Undo가 건너뛴 것이 있다고 합니다.** 캡션이 더 이상 실행이 쓴 내용을 담고 있지 않아서 —
여러분이나 이후의 실행이 바꿨기 때문에 — 그 행은 그대로 두었습니다. 건너뛴 행은 여전히 리포트에
있습니다.

**실행이 잘못된 리포트를 읽거나, 두 스테이지가 하나를 공유합니다.** 각 스테이지는 리포트 루트
아래에 자체 디렉터리(`captions/autotag`, `captions/position`, …)를 가집니다; 루트는 Settings
값 하나이며, 옮기면 전부 함께 옮겨집니다. 비워 두면 리포트는 `dst` 루트 옆에 유지됩니다.

**감사가 내 마스터를 썼는데 되돌리고 싶습니다.** `image_dataset/`는 도구가 버전 관리하지
않습니다; 감사의 `report.json`이 모든 쓰기의 이전 텍스트를 담고 있으며, Undo가 그것을
재생합니다.
