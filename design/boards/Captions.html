The caption card The one place the grammar is visible, and it is visible in the text: every tag wears a box. The boundaries are character offsets from parse_caption over the API — the browser draws where a tag ends, it never decides it. One editor, not one card per tree: the badges above it are the image's caption ladder (CAPTION_LADDER, sidecar labels expanded), filled where the file is on disk, and the panel opens on whichever one the last run wrote.

Anatomy
.card-hkind dot · kind · path · Save — the dot is the same dot as in the tree .hintwhat writes here and what overwrites it — stated, not implied .capwrapthe caption on disk, in mono, edited as one string — the boxes are painted on a backdrop behind a real textarea, so the caret, the selection and the IME stay the browser's. It grows to fit rather than scrolling; its border goes #4b5a80 when dirty .tbone box per tag, cut at the offsets parse_caption returned — the comma between two of them belongs to neither. A plain tag is #565e6e, a clause header #7aa2f7a6 with the tags it owns a step fainter #7aa2f759, an artist handle #e0af68a6, and the tag the caret is inside takes the full accent #7aa2f7 .diffwarn-tinted, left-barred: proposed, not written .tagthe diff's chip — a proposed tag can be questioned before it is applied. Chip or box, asking is the same gesture: .taglens answers in a card under it (category, post count, wiki blurb), one click on a chip and a double-click in the field, where a single click is how you put the caret somewhere
The parse is drawn in place — the caption is never taken apart into chips, because it is not stored as chips. The diff is the one place the grammar becomes a list, through .clause / .tag with + / − colour on top: there, two captions are being compared rather than one edited.
