# anime_tools 指南书

本文档是使用 anime_tools 整理数据集的完整指南：安装、把图像放到位、打开 Web GUI、
按顺序运行描述词 / 分组 / 蒙版各阶段，再把结果发布为一份可直接用于训练的数据集。
它面向通过一行命令安装、从未打开过代码的用户，
说明每个阶段读取什么、写入什么，以及如何把一次运行撤回；
参数本身在每个阶段的表单上，由该阶段自己的 `--help` 生成，各节链接的设计文档对它们有详细解释。

## 1. 这是什么

`anime_tools` 是面向动漫扩散模型训练的数据集整理工具。
它接收一个带有手写描述词的图像文件夹，产出训练所读取的一切：按桶缩放的图像、
经过修正和丰富的描述词、描述词变体、带类型的标签索引、训练蒙版，以及用于精简重复项的分组清单。

它可以独立安装，不含 DiT、不含 VAE，也不需要训练栈里的任何东西；
它写出的每一样都是磁盘上的普通文件，因此产出的数据集可以交给任何训练器。

## 2. 系统要求

| 项目 | 说明 |
|---|---|
| Python | 3.13。安装程序会锁定此版本；机器上没有时 `uv` 会自行获取。 |
| GPU | 可选，但强烈推荐。每个模型阶段（标注器、SAM3、PE-Spatial、OCR）都能在 CPU 上运行，只是速度只有几分之一。torch 能看到 CUDA 时各阶段选用 CUDA，否则选用 CPU。 |
| 操作系统 | Linux、Windows、macOS。macOS 上没有 CUDA 也没有 triton；本包在 SAM3 外面为两者都加了垫片，因此 SAM3 阶段在那里以 CPU 运行。 |
| 磁盘 | 各阶段首次使用时获取的模型（标注器主干网络、SAM3、PE-Spatial、OCR、Danbooru 标签知识库），加上 `workspace/` 下你的数据集的缩放副本。 |

> PyPI 上的 Windows torch 仅支持 CPU，PowerShell 安装程序正因如此默认使用 CUDA 13.0 的
> torch 索引（§3）。PyPI 上的 Linux torch 已自带 CUDA。

## 3. 安装

### 3.1 一行命令，无需检出仓库

Linux / macOS：

```bash
curl -fsSL https://github.com/sorryhyun/anime_tools/releases/latest/download/install.sh | sh
```

Windows（PowerShell）：

```powershell
irm https://github.com/sorryhyun/anime_tools/releases/latest/download/install.ps1 | iex
```

两者都会在缺少 [uv](https://astral.sh/uv) 时先把它装上，然后用 `uv tool install`
把最新 release 装进它自己的虚拟环境（含 torch 与 SAM3），并把 `anime-tools-gui` 放到你的 PATH 上。
不需要 git 检出，也不需要 CUDA 工具包：torch 的 wheel 自带 CUDA 运行时。

两个环境变量控制安装程序：

| 变量 | 效果 |
|---|---|
| `ANIME_TOOLS_VERSION=v0.3.1` | 安装该 tag 而不是最新 release。 |
| `TORCH_INDEX=https://download.pytorch.org/whl/cu128` | torch 的额外包索引。PowerShell 安装程序默认使用 cu132（50 系显卡所需的通道）；需要更旧的 CUDA 运行时请设置此项，完全不用 CUDA 则填 `…/whl/cpu`。在 Linux 上只有构建 CPU-only 版本时才需要。 |

装完后打开一个新的 shell，让 PATH 的变更生效，然后：

```bash
cd <your dataset folder>
anime-tools-gui --open
```

### 3.2 作为你自己项目的依赖

```bash
uv add "anime-tools @ git+https://github.com/sorryhyun/anime_tools"
```

没有 PyPI 包；请锁定一个 tag，或把 `[tool.uv.sources]` 指向一份检出。
有一件事要复制到你自己的 `pyproject.toml` 里：SAM3 锁定了 `numpy<2`，而这个锁定已经过时。
本仓库覆盖了它，但 uv 只认工作区根目录里的 `[tool.uv]`，
所以依赖 anime-tools 的项目必须重复这条覆盖，否则解析会在 numpy 上失败：

```toml
[tool.uv]
override-dependencies = ["numpy>=2.0"]
```

上面的安装程序在命令行上传入了同样的覆盖。

### 3.3 从工具安装运行 CLI

`anime-tools-gui` 是你 PATH 上唯一的命令。要从终端运行某个阶段，请在该工具的环境内运行 Python：

```bash
uv tool run --from anime-tools python -m anime_tools.downloads --list
```

## 4. 整理主目录及其布局

一切都相对于一个目录，即整理主目录（curation home）。按优先级从高到低，它依次是
`ANIME_TOOLS_HOME`、`ANIMA_HOME`（该变量同样有效，因此已在其下建好的目录树无需改动即可使用），
最后是你运行命令时所在的目录。`anime-tools-gui --home <dir>` 为该次服务器运行设置它。

```
<home>/
  (source_dir)/                   INPUT  — your images + hand-written captions; the tools only read it
  workspace/                      everything the tools produce
    resized/<rel>.png               bucket-resized image — the tree every stage reads
    resized/<rel>.txt               the revised caption (stage output)
    resized/<rel>.history.txt       what that caption used to say, one line per version
    resized/<rel>.variants.txt      shuffle / dropout variants, v0 = pristine
    ocr/<rel>.ocr.txt               words in the picture (OCR); not a caption
    masks_sam/                      the SAM3 mask generator's own tree
    masks/<rel>/{stem}_mask.png     the merge — what Export publishes
    captions/<stage>/report.json    what each run did, and how to undo it
    groups/groups.json              the grouping manifest
    _excluded/excluded.json         images you took out of the pipeline
    _excluded/{resized,masks,ocr}/    and the files that moved out with them
  (export_target_dir)/            OUTPUT — the published dataset; written only by Export
  models/                         model weights (ANIME_TOOLS_MODELS overrides)
```

`workspace/` 之外的两个名字只是默认值：它们就是 `src` 和 `out` 两个数据集根，
在 ⚙ Settings（§6.4）里可以指向你已有的任意文件夹。

三条规则解释了你将看到的大部分现象：

- `(source_dir)/` 对各阶段是只读的。你放在那里的描述词是*主描述词*（master）。
  每个阶段都改为在 `workspace/resized/` 下写一份*修订描述词*（revised），
  在还没有修订描述词时回退到主描述词。只有两样东西会写主描述词：
  GUI 里的描述词编辑器（当你手动编辑该梯级时），以及 Export。
- 每个打开图像的阶段都在 `workspace/resized/` 下打开它，蒙版与分组也一样，
  因此整条流水线共用一套几何。只存在于 `(source_dir)/` 中的图像对它们是不可见的。
  这就是 GUI 在任何需要它的阶段之前自动运行 Resize 的原因（§7.1）。
- 除 Export 外没有任何东西写到 `workspace/` 之外（§7.9）。你可以删除工作区再重新生成；
  一条主描述词不会因为某个阶段而丢失。
- `workspace/_excluded/` 是你有意留下的例外：被你移出数据集的图片就在这里（§6.5）。
  其中的任何东西都不会被阶段读取，Export 会把它发布到 `(export_target_dir)/_excluded/` 下 ——
  在训练器读取的那棵树*旁边*，而不是*里面*。

图像文件按主干名（stem）与描述词匹配：`chars/alice/001.png` 读取 `chars/alice/001.txt`。
子文件夹在整条流水线中原样保留（即上面的 `<rel>`）。

> 从工作区之前的安装升级（即直接写 `(export_target_dir)/resized/` 的那种）：
> `python -m anime_tools.workspace.migrate` 打印它将移动的内容，`--apply` 执行移动。
> 它只重命名目录，从不合并：已存在的目标目录会被报告并跳过。
> 你在 ⚙ Settings 中锁定到旧路径的数据集根目录只会被点名，不会被改写，请自行在那里清除。

## 5. Hugging Face 登录与模型

其中两个模型在 Hugging Face Hub 上是门控的：dbv4 标注器主干网络（GPL-3.0，从不随包分发，
加载时以你的 Token 获取）和 SAM 3。两者都需要一个具有 read 权限的 Token，
且 Token 背后的账户必须已各接受过一次相应仓库的条款。

在 GUI 中：☰ → ⚙ Settings… → Hugging Face → 粘贴 Token。它会交给 `huggingface_hub`
的登录流程并由其保存，此后不再显示。设置 Token 之前，页眉会显示 ⚠ no HF token。
Models 列表中的门控行带有一个 accept the terms 链接；请以同一账户登录后打开它。

不需要预先获取任何东西：每个阶段都在首次使用时获取自己需要的模型。
Models & weights 对话框（☰ → Models & weights）为每个检查点列出一行，写明它的用途、
是否已安装、落在何处，并按一起安装的包分组：Tagger、Danbooru tag DB、Masking、OCR、Grouping。
每个包的标题上有一个 Download pack 按钮，每行有自己的 Download，底部还有 Download all N missing。
下载作为普通任务运行，一次一个，与各阶段共用同一个槽位。
这些按钮只是把等待（以及门控仓库可能的拒绝）挪到你自己选定的时刻。

从终端：

```bash
python -m anime_tools.downloads --list        # every row under its pack: installed / MISSING, repo, destination
python -m anime_tools.downloads               # fetch every missing one
python -m anime_tools.downloads sam3 ocr      # fetch by row id or pack id
```

权重落在 `<home>/models/` 下（`ANIME_TOOLS_MODELS` 可覆盖），只有 SAM3 主体软提示例外，
它位于 `networks/calibration/`。

## 6. GUI

```bash
anime-tools-gui --open              # http://127.0.0.1:8790, opens the browser
anime-tools-gui --home ~/datasets/x # a different curation home
anime-tools-gui --host 0.0.0.0      # expose on the LAN (a headless GPU box)
```

如果端口被占用，会改用下一个空闲端口并把它打印出来。`--host 0.0.0.0` **没有任何身份验证**，
请在它前面架设你自己的隧道。服务器本身从不加载模型：每个阶段都作为 `python -m …` 子进程运行，
一次一个，输出流式显示到面板中。

标题栏中数据集名字旁边、以及预览上方图片名字旁边的 ↗，会把那个文件夹或文件交给你自己的文件管理器：
文件夹会被打开，文件会在它所在的文件夹里被选中（而不是用图片查看器打开）。窗口开在跑服务器的那台
机器上，所以只有浏览器与服务器在同一台机器时才会画出这个按钮；隔着局域网就没有 ↗。

### 6.1 侧边栏就是数据集

`(source_dir)/` 下的每张图像，按其文件夹排列，行上的圆点标示存在哪些内容：已缩放、有蒙版，
以及每个描述词梯级一个圆点。每张图像下面，它的描述词构成一个阶梯（ladder），最旧的在前：

| 梯级 | 文件 | 可编辑 |
|---|---|---|
| master | `(source_dir)/<rel>.txt`：手写，各阶段只读取它 | 是 |
| history（`revised@1`、`revised@2`、…） | `<rel>.history.txt`：修订描述词在每次被运行替换之前的内容 | 否 |
| revised | `workspace/resized/<rel>.txt`：阶段输出，下一次运行会改写它，并把此文本保留为一个版本 | 是 |
| variants（`v0`、`v1`、…） | `<rel>.variants.txt`：自动生成，`v0` 是原封未动的修订描述词 | 否 |

filter 框缩小目录树；`↑`/`↓` 或 `j`/`k` 在图像间移动；URL 中的 `#<rel>|<kind>`
是指向某一条描述词的链接。tree / groups 切换以两种顺序绘制同一份列表：按文件夹，
或按 Groups 阶段找到的近似重复分组（§7.7）。带删除线并标有 `⊘` 的行是你排除掉的图片（§6.5）。

### 6.2 描述词编辑器

选中一张图像，会在它的描述词旁边显示图像本身（源图 / 蒙版 / 叠加），
描述词是一个编辑器，每个版本一个徽标。标签包和每个位置从句在文本中用方框标出；
方框来自服务器自己的解析器，因此浏览器从不猜测描述词的结构。
双击一个标签，可以在 Danbooru 标签知识库中查询它（前提是已经下载）。

Save（⌘/Ctrl+Enter）写入 `master` 或 `revised`；其他梯级是只读的。
每次写入都把被替换的文本推入 history 梯级，手动编辑与阶段运行都一样。
保存后会提示接下来该做什么：下游的文本嵌入重新编码总是需要；
如果你编辑的修订描述词已经有 `.variants.txt`，还要重新运行 Correct，因为那份 sidecar 已经过期。

描述词下方，被 OCR 阶段读取过的图像会显示画面中的文字，附每一行的置信度和位置（§7.6）。

在版本徽章之后，被位置阶段（§7.4）看过的图像会多一个 **分析** 徽章。它不是描述词：
选中它，编辑器就换成该阶段看到的东西。它切出的实例蒙版叠画在缩放后的图像上，每个主体一种颜色，
每种颜色旁边列出该主体的位置和从句拿走的标签（或者图像被跳过的原因）。
如果多视图审计阶段看过这张图，它的判定、依据和蒙版也在这里。
这份记录按图像保存在位置报告旁边，所以对别的图像的运行不会动它，对这张图的下一次运行会替换它。

### 6.3 停靠栏就是阶段运行器

底部的按钮条就是阶段列表：Resize 在幕后运行，露出来的按钮是
自动标签 · 标注整理 · OCR 标注 · 分组 · 掩码 · 导出。标注整理容纳两个阶段
（人物位置标注 / 标签校正），掩码也容纳两个（设置 / 合并），在面板内选择。
点击一次打开该阶段的表单；再点一次已打开的按钮，停靠栏会折叠起来。

表单由该阶段自己的 `--help` 生成。打开时显示的是一次运行常常要改的那些参数；
其余的折叠在每个分组底部的 ▸ advanced (n) 之下，某个隐藏字段偏离默认值时会有提示。
数据集根目录、报告根目录和模型路径从不出现在表单上，它们来自 ⚙ Settings。

- Run 只对选中的图像运行该阶段（just `<rel>`）。
- Run batch 对 Settings 中 `path_pattern` 指定的每张图像运行；`*` 就是整个数据集。
- Undo 倒放该阶段上次运行的报告，把它写入前的内容放回去。
- Cancel 停止正在运行的任务。

面板切到中文后，这些按钮显示为 运行 / 批量运行 / 撤销 / 中止，☰ 菜单里的条目显示为
⚙ 设置… / 模型与权重 / 语言。本文沿用英文名称。

Run 会真正写入。GUI 中没有 Apply 这道关卡：一次运行替换掉的内容成为描述词上的版本徽标
（`revised@2`），该次运行的报告在描述词面板中被读回为逐图差异，
而 Undo 就是把两份文本互换后重放这份报告。Undo 有保护：
运行之后你手动编辑过的描述词会被放过，并计为跳过。

最新一行输出显示在阶段栏中，log 按钮打开完整日志。遍历图像的阶段会显示进度条；
前面带有预检的运行会先显示 step 1/2 · resize。

### 6.4 ⚙ Settings 是三个对话框

| 对话框 | 内容 |
|---|---|
| Settings | 整理主目录和模型目录、五个数据集根目录（`src`、`master`、`dst`、`masks`、`out`）、Hugging Face Token。 |
| Advanced settings | 会填进每个接受它们的阶段的阶段默认值（`path_pattern`、标注器目录、SAM3 检查点和软提示、报告根目录、蒙版根目录），以及 Preprocess 区块，也就是 Resize 阶段自己的表单，因为 Resize 没有停靠栏按钮。 |
| Models & weights | §5 中的模型行。 |

每个对话框只保存它自己持有的内容。根目录相对于整理主目录，缺失的根目录会被标记。
面板可以读取已保存设置指向的任何根目录，但只会在主目录之下创建目录，
因此外部根目录里的一处拼写错误只会是一个缺失的根目录，而不会变成一个新的空目录。

☰ 菜单的 Language 行在英语、韩语、日语和中文之间就地切换面板；首次访问跟随浏览器自己的语言列表。
只有面板的外壳会被翻译：阶段的标题、表单标签和帮助来自它的 `--help`，保持英文；
描述词、标签和路径则是数据。

### 6.5 把图片移出流水线

图片名字旁边的 `⊘ exclude` 按钮会把它从数据集中移出，而不删除任何东西。它的缩放副本、
蒙版和 OCR 边车文件都会移进 `workspace/_excluded/`，图片本身则记入那里的台账。此后：

- Resize 会跳过它，因此它不会再回到 `workspace/resized/`；
- 其余所有阶段都遍历那棵树，于是谁也看不见它；
- Export 会把它发布到 `(export_target_dir)/_excluded/` 而不是 `resized/`，
  训练器读不到它，但文件仍然在你手上。

`(source_dir)/` 里的源图片和你手写的主描述词**不会**被动。同一个按钮上的 `↩ put back`
会把每个文件移回原来的树，并把图片从台账中删除，下一次运行各阶段就又能看到它了。

拿它来处理重复的图、裁坏的图，或者干脆和这个 LoRA 无关的图 —— 那些你会删掉、随后又后悔的图。
这里没有 Apply 关卡，运行栏里也没有 Undo：排除*本身*就是那个动作，放回去就是它的逆动作。

## 7. 逐阶段工作流

从上到下依次运行。每个阶段都读取缩放后的目录树，因此一张图像只会经过 Resize 一次；
每个描述词阶段都读取前一个阶段写下的修订描述词。

### 7.1 缩放（Resize，自动运行）

读取 `(source_dir)/`。写入 `workspace/resized/<rel>.png`。

每张图像落入对它缩放最少的桶档位，在该档位的 token 区间内保持原始宽高比。
几何是确定性的，因此重新运行时会发现每张图像都已在自己的桶里并跳过。
低于像素下限（默认 0.5 MP）的图像会被跳过，并在报告中逐个点名：
这样的图像从不被缩放，因此没有任何阶段能看到它。
图像面板会在像素数量小标签上说明这一点，下限则在 ⚙ Advanced settings › Preprocess 中。

你从不需要点它：GUI 把它作为每个读取缩放目录树的阶段的第一步来运行，
而针对单张图像的运行只缩放那一张。已是最新的图像会被跳过，因此预检几乎不花时间。
它总是写入，没有试运行。

> 档位（`target_res`）必须与你的训练流程所预期的一致，否则双方会不断重新缩放对方的输出。

### 7.2 自动标注描述词（Autotag）

读取 每张缩放后的图像及其描述词（有修订描述词就用它，否则用主描述词）。写入 修订描述词。
模型：Anima Tagger（标注器检查点 + 门控的 dbv4 主干网络）。

为每张图像预测一条 Anima 顺序的标签串：`rating, count, characters, copyrights, @artists,
generals`。三种模式：

| 模式 | 作用 |
|---|---|
| `missing`（默认） | 只处理没有任何描述词对应的图像。已有的内容一概不动。 |
| `merge` | 追加描述词里缺少的标签，保留它的位置从句。 |
| `overwrite` | 彻底替换描述词。旧文本作为历史版本保留。 |

只有 `missing` 是非破坏性的；另外两种可以通过 history 梯级和 Undo 撤销。
请把输出当作起点，训练前先核对名字、系列和艺术家。
标注器本身见 [`docs/anima_tagger.md`](../../../docs/anima_tagger.md)。

### 7.3 修正并镜像描述词（Correct）

读取 主描述词和 Danbooru 标签知识库。写入 修订描述词，以及可选的 `.variants.txt`。

把每条主描述词镜像成一条修正过的修订描述词：标签按知识库确定类型并排入 Anima 的桶序，
可选地插入一个触发词，可选地加上 `@no-artist` 哨兵标记，还可以设置丢弃组（drop groups），
从每条镜像出的描述词中剥掉整个标签族而不碰主描述词。设置了变体数量时，
它还会写 `<rel>.variants.txt`：`v0` 是修正后的描述词，`v1…` 是智能打乱和 dropout 抽样，
下游会原样编码它们。

总是写入；没有试运行也没有报告，因此也没有 Undo，被替换的文本留在 history 梯级上。
知识库是 Models 中的 Danbooru tag KB 行（§5），它可选的英文行会改写标签查询所显示的描述。

> Correct 镜像的是主描述词。修订描述词的位置从句能在重新运行后存留
> （它们会被重新附加到新的镜像上），但 Autotag `merge` 添加到扁平标签包里的标签不会，
> 所以请在 Autotag `merge` 之前运行 Correct，而不是之后。

### 7.4 位置描述词（Position）

读取 缩放后的图像及其描述词。写入 修订描述词。模型：SAM 3（门控）、主体软提示、
Anima Tagger。

对于有两个或更多主体的图像，它检测出每一个主体，按阅读顺序排列，
为每个主体的蒙版遮空裁剪图打标签，然后把描述词改写成位置从句语法：
`<flat tag bag>. On the left, …. On the right, ….` 属于某一个主体的标签会从扁平标签包
移进该主体的从句；除一小份宽限外，不会凭空发明整理过的描述词从未说过的内容。
单主体图像会被跳过，并在报告中说明原因。

一次 apply 会丢弃它改写过的描述词旁边任何过期的 `.variants.txt`。撤回它有自己的模式
`--flatten`，它不加载任何模型，把每个从句合并回扁平标签包；也可以直接用 Undo。
完整的语法、门槛和每个参数都在 [`docs/position_captions.md`](../../../docs/position_captions.md) 中。

### 7.5 多视图审计（Audit）

它没有自己的按钮：它作为位置阶段的第一步运行，由该表单的 `multiview_audit` 设定
（`report` 只审计、不打任何标签，`apply` 还会把每个被采纳的判定送进同一次运行的扫描）。
它的 CLI 仍可单独运行它。

读取 位置阶段跳过的单主体图像。写入 修订描述词：把 `multiple views`
追加到扁平标签包末尾，且仅此而已。模型：与 Position 相同。

找出实为同一个女孩多个视图的 `1girl` 图像，并在报告目录下用一张拼版预览图（contact sheet）
逐张报告。apply 默认只放行强判定；弱判定背后只有几何依据，所以请先看它的拼版图。

> 手写的主描述词从不会被碰。apply 替换掉的文本会作为历史版本保留，Undo 会重放报告。
> 见 [`docs/multiview_audit.md`](../../../docs/multiview_audit.md)。

### 7.6 OCR 文字（OCR）

读取 缩放后的图像。写入 `workspace/ocr/<rel>.ocr.txt`。模型：AnimeText 文字块检测器
（找出气泡对白，也找出画在画面上的拟声词）和漫画 VL 阅读器（读取找到的每一个框，
日文、中文、英文都读，爱心、小假名和手写拟声词也读）。两者都在 Models & weights 的 OCR 包里。

记录画面中的文字（对白、招牌、拟声词），每个文字块一条，附位置。它不是描述词：
下游没有任何东西编码它，它不读也不写任何描述词，之后也不需要重新编码。图像面板会显示这些行。
默认丢弃纯 ASCII 的行（页码、URL）；一个气泡就是一个文字块，所以它的各列会合成一行到达。

### 7.7 构建分组（Groups）

读取 缩放后的图像。写入 `workspace/groups/groups.json`。模型：PE-Spatial。

按顶层文件夹，依据视觉内容而不是文件名或描述词，把几乎相同的图像（重复项、替代版本、
同一张画的裁剪）聚成一组。侧边栏的 groups 顺序就是这个结果：每组一个可折叠的标题，
于是冗余内容聚在一起，便于精简。过滤器和待处理圆点在两种顺序下含义相同。

重新运行成本很低：特征缓存在 `~/.cache/near_twin/` 下（`NEAR_TWIN_CACHE` 可覆盖），
并盖有文件大小和 mtime 的印记，因此重新缩放之后只会重算真正变了的图像。
用表单上的两个匹配阈值收紧或放宽聚类。见 [`docs/grouping.md`](../../../docs/grouping.md)。

### 7.8 蒙版：设置、合并（掩码）

读取 缩放后的图像。写入 `workspace/masks_sam/`，以及它在 `workspace/masks/` 下的合并结果：
8 位 `{stem}_mask.png`，镜像源子文件夹。模型：SAM 3。

- 设置是一张蒙版列表，每行一个蒙版：一个角色，**保留**（只训练保留的区域）或 **排除**
  （这块区域不计入损失），和一个类型，**文本**（像 `speech bubble` 这样的 SAM3 提示词）或
  **软提示**（学出来的提示文件，`.safetensors`）。+ 添加一行，× 去掉一行。默认是一行，
  用随附的软提示保留主体；气泡和文字在这里只是普通的排除行。
- Merge 取各输入树的逐像素最小值写入 `workspace/masks/`，这就是侧边栏显示为 mask /
  overlay、并由 Export 发布的那棵树。默认输入是生成器的树；缺失的输入会被跳过，
  也可以在旁边列出一棵手绘的树。

这两个目录是一个设置而不是两个字段，因为在生成器的树旁边合并进来的第二棵树会给蒙版起
同样的名字，在共享的树里把它覆盖掉。蒙版总是写入；要改动某一个就重新生成。
见 [`docs/masking.md`](../../../docs/masking.md)。

### 7.9 导出工作区（Export）

读取 工作区。写入 `(export_target_dir)/`；若主描述词有修订，也写入 `(source_dir)/`。

唯一写到工作区之外的阶段。它发布六种产物（缩放图像、修订描述词、变体 sidecar、蒙版、
修订过的主描述词、描述词索引），每一种都各自对照它的目标位置来决定：相同的文件会被跳过
（文本按字节比较，像素按大小和 mtime），因此重新导出一份未改动的数据集只是一次遍历
加每个文件一次 stat。它总是复制，从不做链接，因此工作区被清空后导出树依然完整。

从 CLI 运行时默认是试运行，列出它将复制的内容。在 GUI 中 Run 执行复制，
Undo 依据导出自己的账本恢复它覆盖过的文本；被覆盖的像素无法恢复，会如实报告。
离开工作区的只有 Export 写下的内容。

它是唯一没有单张图像 Run、也不接受 `path_pattern` 的阶段：一次发布就是整个工作区。
只发布一张图像，结果会落在训练器仍然当作整个数据集来读的树旁边，
这与按下 Export 想要的恰好相反。

## 8. CLI 等价命令

每个阶段都是一个 `python -m` 模块，作用于 GUI 表单所填的同一个请求对象，
每个表单字段对应一个标志（`--help` 会列出它们）。路径相对于整理主目录。
描述词阶段用下划线拼写标志（`--path_pattern`），分组和蒙版用连字符（`--source-dir`）；
两种拼写在任何地方都被接受。

| 阶段 | 模块 | 不带 `--apply` 时是否写入？ |
|---|---|---|
| Resize | `anime_tools.stages.cli.resize_images` | 总是写入 |
| Autotag | `anime_tools.stages.cli.autotag_captions` | 试运行 → `report.json` |
| Position | `anime_tools.stages.cli.position_captions` | 试运行 → `report.json` |
| Correct | `anime_tools.stages.cli.correct_captions` | 总是写入 |
| Audit | `anime_tools.stages.cli.audit_multiview` | 试运行 → `report.json` |
| OCR | `anime_tools.stages.cli.ocr_captions` | 试运行 → `report.json` |
| Groups | `anime_tools.grouping.cli.build_groups` | 总是写入 `groups.json` |
| SAM3 masks | `anime_tools.masking.cli.generate_masks` | 总是写入 |
| Merge masks | `anime_tools.masking.cli.merge_masks` | 总是写入 |
| Export | `anime_tools.stages.cli.export_workspace` | 试运行 → `report.json` |
| 排除（§6.5） | `anime_tools.exclude` | 试运行 → 打印将要移动的内容 |

试运行的阶段把 `report.json` 写到 `workspace/captions/<stage>/` 下然后停止，`--apply` 才真正写入。
位置描述词（Position）和多视图审计（Audit）还接受 `--from_report <report.json>`，
它不加载模型就重放一次试运行的提案，跳过其间发生了变化的描述词，
并在它读取的报告旁写下 `apply_report.json`。Autotag 没有这个标志：
它的一趟只是每张图像一次前向，重跑比算出该跳过什么更便宜。GUI 的 Undo 就是同一份重放的倒放。

```bash
python -m anime_tools.stages.cli.autotag_captions --mode merge            # dry run
python -m anime_tools.stages.cli.autotag_captions --mode merge --apply    # write
python -m anime_tools.stages.cli.export_workspace --apply                 # publish

python -m anime_tools.exclude char_aki/bad.jpg --note "bad crop" --apply  # take one out
python -m anime_tools.exclude --list                                     # what is out
python -m anime_tools.exclude char_aki/bad.jpg --restore --apply         # put it back
```

Python API 是同一个对象：[`examples/`](../../../examples/README.md) 中每个功能有一个可运行的脚本，
API 与 CLI 并列。

## 10. 故障排除

某个阶段因门控仓库错误失败（来自 Hub 的 401 / 403）。
Token 缺失，或该账户尚未接受该仓库的条款。在 ⚙ Settings 中设置 Token，
然后以同一账户登录，打开 Models & weights 中该行的 accept the terms 链接。
Download 按钮能在不完整跑一遍阶段的情况下复现这个失败。

`uv` 在我自己的项目里解析 numpy 失败。
SAM3 那条过时的 `numpy<2` 锁定。把 §3.2 的覆盖加到你的 `pyproject.toml` 中。

macOS：`import sam3` 抱怨 triton，或张量无法放到 `cuda` 上。
两者都在本包的 SAM3 加载器内部处理掉了；如果你看到它们，
说明你在自行导入 sam3，或者在运行旧的 release。SAM3 阶段在那里以 CPU 运行，很慢。

Windows：torch 没有 CUDA。
PyPI 的 Windows torch 仅支持 CPU。用默认使用 CUDA 索引的 PowerShell 安装程序重新安装，
或者显式设置 `TORCH_INDEX`。

某个阶段看不到任何图像 / 对这张图像什么都不做。
该图像不在 `workspace/resized/` 下。要么它低于缩放下限
（像素数量小标签会这样说；在 ⚙ Advanced settings › Preprocess 中调低下限），
要么 `src` 根目录没有指向你的数据集。

"saved — .variants.txt is now stale"。
你编辑了一条带有变体的修订描述词。用相同的变体数量重新运行 Correct，
然后在下游重新编码文本嵌入。

Undo 说它跳过了一些东西。
描述词已不再是那次运行写下的内容，你或者后来的某次运行改动了它，因此那一行被放过了。
被跳过的行仍然在报告里。

某次运行读取了错误的报告，或者两个阶段共用一份。
每个阶段在报告根目录下有自己的目录（`captions/autotag`、`captions/position`、…）；
根目录是一个 Settings 值，移动它会把它们全部移动。留空则报告放在 `dst` 根目录旁边。
