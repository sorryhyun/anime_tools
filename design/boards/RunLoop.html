The run bar The interaction model the whole GUI is built around: a run writes, and the text it replaced is still there — one badge to the left.
Run
Loads the models and writes — the captions and report.json both. No gate in front of it.
the version
What it replaced, kept as revised@2 on the ladder — plus the report, read back as the diff under the editor.
Undo
Replays that exact report backwards — no model loads. A caption edited since is skipped, not overwritten.

Rules the bar encodes
→Exactly one .primary — the button that writes. Greyed until allowed, never moved.
→Run is this image; Run batch is the Settings pattern.
→A disabled button keeps its tooltip — hovering says why.
→Red never appears in the bar. There is no confirm dialog either — the ladder keeps the old text, so a run needs no promise.
One button, two jobs
Undo idle Cancel running
The same slot: nothing to undo while something runs, and a long pass must stay stoppable. Undo restores the run report's before-text, skipping any caption edited since — and is itself a write, so it leaves a version too.
The dock is the only thing that runs Python — but not the only thing that writes. A caption you retype goes straight to disk on Save. Both kinds of write are immediate now, and both leave the same trail: yours is filed under edit, the machine's under the stage that made it.
