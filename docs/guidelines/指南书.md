# anime_tools 指南书

本文档是使用 **anime_tools** 整理数据集的从头到尾的指南：安装、把图像放到位、打开 Web GUI、
按顺序运行描述词 / 分组 / 蒙版各阶段，再把结果交给
[Anima LoRA 训练器](https://github.com/sorryhyun/anima_lora)。
它面向通过一行命令安装程序完成安装、从未打开过代码的用户。
它说明每个阶段读取什么、写入什么，以及如何把一次运行撤回；
各项参数本身在每个阶段的表单上，由该阶段自己的 `--help` 生成，各节链接的设计文档对它们有详细解释。

## 1. 这是什么

`anime_tools` 是 Anima LoRA 训练器中负责数据集整理的那一半，拆分出来以便单独运行：
安装体积更小，不含 DiT 和 VAE，而且它产出的数据集可以交给任何训练器。
它接收一个带有手写描述词的图像文件夹，产出训练器在训练前读取的一切——按桶缩放的图像、
经过修正和丰富的描述词、描述词变体、带类型的标签索引、训练蒙版，以及用于精简重复项的分组清单。

训练器依赖本包；本包从不导入训练器。两者约定的一切——文件名、描述词语法、各项产物落在何处——
都在 [`docs/contract.md`](../contract.md) 中写明一次。

## 2. 系统要求

| 项目 | 说明 |
|---|---|
| Python | **3.13**。安装程序会锁定此版本；机器上没有时 `uv` 会自行获取。 |
| GPU | 可选，但强烈推荐。每个模型阶段（标注器、SAM3、PE-Spatial、文本分割器、OCR）都能在 CPU 上运行，只是速度仅为几分之一。torch 能看到 CUDA 时各阶段选用 CUDA，否则选用 CPU。 |
| 操作系统 | Linux、Windows、macOS。macOS 上没有 CUDA 也没有 triton；本包为 SAM3 对两者都做了兼容垫片，因此 SAM3 阶段在那里以 CPU 运行。 |
| 磁盘 | 各阶段首次使用时获取的模型（标注器主干网络、SAM3、PE-Spatial、文本网络、OCR、Danbooru 标签知识库），加上 `workspace/` 下你的数据集的缩放副本。 |

> **PyPI 上的 Windows torch 仅支持 CPU。** 正因如此，PowerShell 安装程序默认使用 CUDA 13.0 的
> torch 索引（§3）。PyPI 上的 Linux torch 已自带 CUDA。

## 3. 安装

### 3.1 一行命令，无需检出仓库

Linux / macOS：

```bash
curl -fsSL https://github.com/sorryhyun/anime_tools/releases/latest/download/install.sh | sh
```

Windows（PowerShell）：

```powershell
irm https://github.com/sorryhyun/anime_tools/releases/latest/download/install.ps1 | iex
```

两者都会在 [uv](https://astral.sh/uv) 缺失时安装它，然后用 `uv tool install` 把最新 release
装进它自己的虚拟环境（torch 与 SAM3 包含在内），并把 `anime-tools-gui` 放到你的 PATH 上。
不需要 git 检出，也不需要 CUDA 工具包：torch 的 wheel 自带 CUDA 运行时。

两个环境变量控制安装程序：

| 变量 | 效果 |
|---|---|
| `ANIME_TOOLS_VERSION=v0.3.1` | 安装该 tag 而不是最新 release。 |
| `TORCH_INDEX=https://download.pytorch.org/whl/cu130` | torch 的额外包索引。PowerShell 安装程序已默认使用此索引；在 Linux 上只有构建 CPU-only 版本时才需要（`…/whl/cpu`）。 |

完成后，打开一个**新的 shell** 以便 PATH 的变更生效，然后：

```bash
cd <your dataset folder>
anime-tools-gui --open
```

### 3.2 作为你自己项目的依赖

```bash
uv add "anime-tools @ git+https://github.com/sorryhyun/anime_tools"
```

没有 PyPI 包；请锁定一个 tag，或把 `[tool.uv.sources]` 指向一份检出。
有一件事要复制到你自己的 `pyproject.toml` 里：SAM3 锁定了 `numpy<2`，而这个锁定已经过时。
本仓库覆盖了它，但 uv 只在工作区根目录尊重 `[tool.uv]`，所以*依赖* anime-tools
的项目必须重复这条覆盖，否则解析会在 numpy 上失败：

```toml
[tool.uv]
override-dependencies = ["numpy>=2.0"]
```

上面的安装程序在命令行上传入了同样的覆盖。

### 3.3 从工具安装运行 CLI

`anime-tools-gui` 是你 PATH 上唯一的命令。要从终端运行某个阶段，请在该工具的环境内运行 Python：

```bash
uv tool run --from anime-tools python -m anime_tools.downloads --list
```

## 4. 整理主目录及其布局

一切都相对于一个目录，即**整理主目录**（curation home）。按优先级顺序，它是 `ANIME_TOOLS_HOME`，
其次是 `ANIMA_HOME`（训练器自己的主目录，因此训练器使用的目录树无需改动即可使用），
最后是你运行命令时所在的目录。`anime-tools-gui --home <dir>` 为该服务器设置它。

```
<home>/
  image_dataset/                  INPUT  — your images + hand-written captions; the tools only read it
  workspace/                      everything the tools produce
    resized/<rel>.png               bucket-resized image — the tree every stage reads
    resized/<rel>.txt               the revised caption (stage output)
    resized/<rel>.history.txt       what that caption used to say, one line per version
    resized/<rel>.variants.txt      shuffle / dropout variants, v0 = pristine
    ocr/<rel>.ocr.txt               words in the picture (OCR); not a caption
    masks_sam/  masks_mit/          each mask generator's own tree
    masks/<rel>/{stem}_mask.png     the merge of the two — what Export publishes
    captions/<stage>/report.json    what each run did, and how to undo it
    groups/groups.json              the grouping manifest
  post_image_dataset/             OUTPUT — written only by Export; the tree the trainer reads
  models/                         model weights (ANIME_TOOLS_MODELS overrides)
```

三条规则解释了你将看到的大部分现象：

- **`image_dataset/` 对各阶段是只读的。** 你放在那里的描述词是*主描述词*（master）。
  每个阶段都改为在 `workspace/resized/` 下写一份*修订描述词*（revised），
  在尚无修订描述词时回退到主描述词。只有两样东西会写主描述词：
  GUI 中的描述词编辑器（当你手动编辑该梯级时），以及 Export。
- **每个打开图像的阶段都在 `workspace/resized/` 下打开它**——蒙版与分组也包括在内，
  因此整条流水线共用一套几何。只存在于 `image_dataset/` 中的图像对它们是不可见的。
  这就是 GUI 在任何需要它的阶段之前自动运行 Resize 的原因（§7.1）。
- **除 Export 外没有任何东西写到 `workspace/` 之外**（§7.9）。你可以删除工作区再重新生成；
  你不会因某个阶段而丢失一条主描述词。

图像文件按主干名（stem）与描述词匹配：`chars/alice/001.png` 读取 `chars/alice/001.txt`。
子文件夹在整条流水线中原样保留（即上面的 `<rel>`）。

> **从工作区之前的安装升级**（即直接写 `post_image_dataset/resized/` 的那种）：
> `python -m anime_tools.workspace.migrate` 打印它将移动的内容，`--apply` 执行移动。
> 它只重命名目录，从不合并：已存在的目标目录会被报告并跳过。
> 你在 ⚙ Settings 中锁定到旧路径的数据集根目录会被点名但不会改写——请自行在那里清除它。

## 5. Hugging Face 登录与模型

其中两个模型在 Hugging Face Hub 上是**门控**的：dbv4 标注器主干网络（GPL-3.0，从不随包分发——
它在加载时以*你的* Token 获取）和 SAM 3。两者都需要具有 read 权限的 Token，
且 Token 背后的账户必须已各接受过一次相应仓库的条款。

在 GUI 中：☰ → **⚙ Settings…** → *Hugging Face* → 粘贴 Token。它会交给 `huggingface_hub`
的登录并由其保存，此后不再显示。在设置 Token 之前，页眉会显示 **⚠ no HF token**。
Models 列表中的门控行带有一个 *accept the terms* 链接；请以同一账户登录后打开它。

不需要预先获取任何东西：**每个阶段都在首次使用时获取自己需要的模型。**
**Models & weights** 对话框（☰ → *Models & weights*）为每个检查点列出一行——它的用途、
是否已安装、落在何处——每行有一个 **Download** 按钮，另有 **Download all N missing**。
下载作为普通任务运行，一次一个，与各阶段共用同一个槽位。
这些按钮只是把等待（以及任何门控仓库的拒绝）挪到你自己选定的时刻。

从终端：

```bash
python -m anime_tools.downloads --list        # every row: installed / MISSING, repo, destination
python -m anime_tools.downloads               # fetch every missing one
python -m anime_tools.downloads sam3 tagger   # fetch by id
```

权重落在 `<home>/models/` 下（`ANIME_TOOLS_MODELS` 可覆盖），SAM3 主体软提示除外，
它位于 `networks/calibration/`，因为训练器把它放在那里。

## 6. GUI

```bash
anime-tools-gui --open              # http://127.0.0.1:8790, opens the browser
anime-tools-gui --home ~/datasets/x # a different curation home
anime-tools-gui --host 0.0.0.0      # expose on the LAN (a headless GPU box)
```

如果端口被占用，会使用并打印下一个空闲端口。`--host 0.0.0.0` **没有任何身份验证**——
请在它前面架设你自己的隧道。服务器本身从不加载模型：每个阶段都作为 `python -m …` 子进程运行，
一次一个，其输出流式显示到面板中。

### 6.1 侧边栏就是数据集

`image_dataset/` 下的每张图像，按其文件夹排列，行上的圆点标示存在哪些内容：已缩放、有蒙版，
以及每个描述词梯级一个圆点。每张图像下，它的描述词构成一个**阶梯**（ladder），最旧的在前：

| 梯级 | 文件 | 可编辑 |
|---|---|---|
| **master** | `image_dataset/<rel>.txt`——手写；各阶段只读取它 | 是 |
| **history**（`revised@1`、`revised@2`、…） | `<rel>.history.txt`——修订描述词在每次被替换的运行之前的内容 | 否 |
| **revised** | `workspace/resized/<rel>.txt`——阶段输出；下一次运行会改写它，并把此文本保留为一个版本 | 是 |
| **variants**（`v0`、`v1`、…） | `<rel>.variants.txt`——生成的；`v0` 是原封未动的修订描述词 | 否 |

**filter** 框缩小目录树；`↑`/`↓` 或 `j`/`k` 在图像间移动；URL 中的 `#<rel>|<kind>`
是指向某一条描述词的链接。**tree / groups** 切换以两种顺序绘制同一份列表——按文件夹，
或按 Groups 阶段找到的近似重复分组（§7.7）。

### 6.2 描述词编辑器

选中一张图像会在其描述词旁边显示它（源图 / 蒙版 / 叠加），一个编辑器，每个版本一个徽标。
标签包和每个位置从句在文本中用方框标出；方框来自服务器自己的解析器，因此浏览器从不猜测描述词的结构。
双击一个标签可在 Danbooru 标签知识库中查询它（下载之后）。

**Save**（⌘/Ctrl+Enter）写入 `master` 或 `revised`；其他梯级是只读的。
每次写入都把被替换的文本推入 history 梯级，手动与阶段皆然。保存后会告诉你接下来该做什么：
训练器的文本编码器重新编码总是需要；而当你编辑的修订描述词已经有 `.variants.txt` 时，
还要*重新运行 Correct*，因为那份 sidecar 现在已过期。

描述词下方，被 OCR 阶段读取过的图像会显示**图像中的文字**，附每一行的置信度和位置（§7.6）。

### 6.3 停靠栏就是阶段运行器

底部的按钮条**就是阶段列表**：Resize 在幕后运行，按钮是
**Autotag · Curate · OCR · Groups · Masks · Export**。Curate 容纳三个阶段
（Position / Correct / Audit），Masks 容纳三个（Subject / Text / Merge），在面板内选择。
点击一次打开该阶段的表单；再次点击已打开的按钮会把停靠栏折叠起来。

表单由该阶段自己的 `--help` 生成。打开时显示的是一次运行会改变主意的那些参数；
其余的折叠在每个分组底部的 **▸ advanced (n)** 之下，若某个隐藏字段偏离了默认值会有提示。
数据集根目录、报告根目录和模型路径从不出现在表单上——它们来自 ⚙ Settings。

- **Run** 只对选中的图像运行该阶段（**just `<rel>`**）。
- **Run batch** 对 Settings 中 `path_pattern` 指定的每张图像运行——`*` 即整个数据集。
- **Undo** 通过倒放该阶段上次运行的报告，放回它所写入的内容。
- **Cancel** 停止正在运行的任务。

面板切到中文后，这些按钮显示为 **运行 / 批量运行 / 撤销 / 中止**，☰ 菜单里的条目显示为
**⚙ 设置… / 模型与权重 / 语言**。本文沿用英文名称。

**Run 会真正写入。** GUI 中没有 Apply 这道关卡：一次运行替换掉的内容成为描述词上的版本徽标
（`revised@2`），该次运行的报告在描述词面板中被读回为逐图差异，
而 Undo 就是把两份文本互换后重放该报告。Undo 有保护：
运行之后你手动编辑过的描述词会被放过并计为跳过。

最新一行输出显示在阶段栏中；**log** 按钮打开完整日志。遍历图像的阶段会显示进度条；
前面带有预检的运行会先显示 *step 1/2 · resize*。

### 6.4 ⚙ Settings 是三个对话框

| 对话框 | 内容 |
|---|---|
| **Settings** | 整理主目录和模型目录、五个**数据集根目录**（`src`、`master`、`dst`、`masks`、`out`）、Hugging Face Token。 |
| **Advanced settings** | 填入每个接受它们的阶段的**阶段默认值**（`path_pattern`、标注器目录、SAM3 检查点和软提示、报告根目录、蒙版根目录），以及 **Preprocess** 区块——即 Resize 阶段自己的表单，因为 Resize 没有停靠栏按钮。 |
| **Models & weights** | §5 中的模型行。 |

每个对话框只保存它自己持有的内容。根目录相对于整理主目录；缺失的根目录会被标记。
面板可以*读取*已保存设置指向的任何根目录，但只会在主目录之下*创建*目录，
因此外部根目录中的一处拼写错误只是一个缺失的根目录，而不会变成一个新的空目录。

☰ 菜单的 **Language** 行在英语、韩语、日语和中文之间就地切换面板；首次访问遵循浏览器自己的语言列表。
只有面板的外壳被翻译——阶段的标题、表单标签和帮助来自它的 `--help`，保持英文；
描述词、标签和路径则是数据。

## 7. 逐阶段工作流

从上到下运行它们。每个阶段都读取缩放后的目录树，因此一张图像只会经过 Resize 一次；
每个描述词阶段都读取前一个阶段写下的修订描述词。

### 7.1 缩放（Resize，自动运行）

**读取** `image_dataset/`。**写入** `workspace/resized/<rel>.png`。

每张图像落入对它缩放最少的桶档位，在该档位的 token 区间内保持其原始宽高比。
几何与训练器的相同，因此无论哪一方先缩放，另一方都会发现每张图像已在其桶中并跳过它。
低于像素下限（默认 0.5 MP）的图像会**被跳过并在报告中点名**——这样的图像从不被缩放，
因此没有阶段能看到它；图像面板会在像素数量小标签上说明这一点，
下限则在 ⚙ Advanced settings › Preprocess 中。

你从不需要点击它：GUI 把它作为每个读取缩放目录树的阶段的第一步来运行，
而针对单张图像的运行只缩放那一张。已是最新的图像会被跳过，因此预检几乎不花时间。
总是写入；没有试运行。

> 档位（`target_res`）必须与训练器的一致，否则双方会不断重新缩放对方的输出。

### 7.2 自动标注描述词（Autotag）

**读取** 每张缩放后的图像及其描述词（修订描述词，否则主描述词）。**写入** 修订描述词。
**模型**：Anima Tagger（标注器检查点 + 门控的 dbv4 主干网络）。

为每张图像预测一条 Anima 顺序的标签串——`rating, count, characters, copyrights, @artists,
generals`。三种模式：

| 模式 | 作用 |
|---|---|
| `missing`（默认） | 只处理**没有任何描述词对应**的图像。已有的内容一概不动。 |
| `merge` | 追加描述词缺少的标签，保留其位置从句。 |
| `overwrite` | 彻底替换描述词。旧文本作为历史版本保留。 |

只有 `missing` 是非破坏性的；另外两种可以通过 history 梯级和 Undo 撤销。
请把输出视为起点——训练前检查名字、系列和艺术家。
标注器本身见 [`docs/anima_tagger.md`](../anima_tagger.md)。

### 7.3 修正并镜像描述词（Correct）

**读取** 主描述词和 Danbooru 标签知识库。**写入** 修订描述词，以及可选的 `.variants.txt`。

把每条主描述词镜像为一条修正过的修订描述词：标签按知识库确定类型并排入 Anima 的桶序，
可选地插入一个触发词，可选地加上 `@no-artist` 哨兵标记，以及可选的**丢弃组**（drop groups），
从每条镜像出的描述词中剥离整个标签族而不触碰主描述词。设置了变体数量时，
它还会写 `<rel>.variants.txt`：`v0` 是修正后的描述词，`v1…` 是智能打乱和 dropout 抽样，
训练器会原样编码它们。

总是写入；没有试运行也没有报告，因此也没有 Undo——被替换的文本在 history 梯级上。
知识库是 Models 中的 **Danbooru tag KB** 行（§5）；其可选的英文行会改写标签查询所显示的描述。

> Correct 镜像的是**主描述词**。修订描述词的位置从句能在重新运行后存留
> （它们会被重新附加到新的镜像上），但 Autotag `merge` 添加到扁平标签包里的标签不会，
> 所以请在 Autotag `merge` 之前运行 Correct，而不是之后。

### 7.4 位置描述词（Position）

**读取** 缩放后的图像及其描述词。**写入** 修订描述词。**模型**：SAM 3（门控）、主体软提示、
Anima Tagger。

对于有两个或更多主体的图像，检测每一个主体，按阅读顺序排列，对每个主体经蒙版遮空的裁剪图打标签，
然后把描述词改写为位置从句语法：`<flat tag bag>. On the left, …. On the right, ….`
属于某一个主体的标签会从扁平标签包*移动*到该主体的从句中；
除一小份宽限外，不会凭空发明整理过的描述词从未说过的内容。单主体图像会被跳过，并在报告中说明原因。

一次 apply 会丢弃它所改写的描述词旁边任何过期的 `.variants.txt`。**撤回它**有自己的模式
`--flatten`，它在不加载任何模型的情况下把每个从句合并回扁平标签包——或者用 Undo。
完整的语法、门槛和每个参数都在 [`docs/position_captions.md`](../position_captions.md) 中。

### 7.5 多视图审计（Audit）

**读取** 位置阶段跳过的单主体图像。**写入** `multiple views` 到**主描述词**中，且仅此而已。
**模型**：与 Position 相同。

找出实为同一女孩多个视图的 `1girl` 图像，并在报告目录下用一张拼版预览图（contact sheet）
报告每一张。apply 默认只放行强判定；弱判定背后只有几何依据，所以请先查看它的拼版图。

> 这是唯一直接写 `image_dataset/` 的阶段。报告保存每次写入之前的文本，Undo 会把它读回。
> 见 [`docs/multiview_audit.md`](../multiview_audit.md)。

### 7.6 OCR 文字（OCR）

**读取** 缩放后的图像。**写入** `workspace/ocr/<rel>.ocr.txt`。**模型**：PP-OCRv6 检测 + 识别
（英文、中文、日文；不含韩文）。

记录*画面中的*文字——对白、招牌、拟声词——每行一条，附置信度和位置。它**不是描述词**：
下游没有任何东西编码它，不读也不写任何描述词，之后也不需要重新编码。图像面板会显示这些行。
默认丢弃纯 ASCII 的行（页码、URL），并把竖排日文列合并为每个气泡一行。

### 7.7 构建分组（Groups）

**读取** 缩放后的图像。**写入** `workspace/groups/groups.json`。**模型**：PE-Spatial。

按顶层文件夹，依据视觉内容而非文件名或描述词，把几乎相同的图像——重复项、替代版本、
同一张画的裁剪——聚成一组。侧边栏的 **groups** 顺序绘制结果：每组一个可折叠的标题，
于是冗余内容聚在一起，便于精简。过滤器和待处理圆点在两种顺序下含义相同。

重新运行成本很低：特征缓存在 `~/.cache/near_twin/` 下（`NEAR_TWIN_CACHE` 可覆盖），
并盖有文件大小和 mtime 的印记，因此重新缩放后只会重算真正变化了的图像。
用表单上的两个匹配阈值收紧或放宽聚类。见 [`docs/grouping.md`](../grouping.md)。

### 7.8 蒙版：Subject、Text、Merge（Masks）

**读取** 缩放后的图像。**写入** `workspace/masks_sam/`、`workspace/masks_mit/`，
以及二者在 `workspace/masks/` 下的合并——8 位 `{stem}_mask.png`，镜像源子文件夹。
**模型**：两个生成器都用 SAM 3；Text 还用漫画文字分割器和 ComicTextDetector 门控。

- **Subject** 保留主体并把背景蒙掉：默认以学得的主体提示为 SAM3 定位。
  可以添加要*蒙掉*的提示（`speech bubble,text`）。
- **Text** 用两个检测器蒙住文字和气泡，各自有独立开关——基于提示的 SAM3（气泡是一个形状）
  和 UNet++ 分割器（字母是一道笔画）——在一次膨胀之前取并集。两者都关闭是该阶段唯一拒绝的表单。
- **Merge** 取两棵树的逐像素最小值写入 `workspace/masks/`，这就是侧边栏显示为 *mask* /
  *overlay* 且由 Export 发布的那棵树。缺失的输入树会被跳过，所以只运行一个生成器也是有效的一半。

这三个目录是一个设置而不是三个字段，因为两个生成器给蒙版起的名字完全相同，
在共享的树中会互相覆盖。蒙版总是写入；要改动某一个就重新生成。见 [`docs/masking.md`](../masking.md)。

### 7.9 导出工作区（Export）

**读取** 工作区。**写入** `post_image_dataset/`——以及，对于修订过的主描述词，`image_dataset/`。

唯一写到工作区之外的阶段。它发布六种产物——缩放图像、修订描述词、变体 sidecar、蒙版、
修订过的主描述词、描述词索引——每一种都各自对照其目标位置决定：相同的文件被跳过
（文本按字节比较，像素按大小和 mtime），因此重新导出一个未改动的数据集只是一次遍历加每个文件一次
stat。它总是**复制**，从不链接，因此导出树在工作区被清空后依然存在。

从 CLI 运行时默认是试运行，列出它将复制的内容。在 GUI 中 **Run** 执行复制，
**Undo** 依据导出自己的账本恢复它覆盖过的文本；被覆盖的*像素*无法恢复，并会如实报告。
训练器只读取 Export 写下的内容——每条路径见 [`docs/contract.md`](../contract.md) §2。

## 8. 交接给训练器

1. **Export**（§7.9）。训练器从 `post_image_dataset/resized/` 读取图像和修订描述词，
   从 `post_image_dataset/masks/` 读取蒙版，从 `image_dataset/` 读取主描述词。
2. 在训练器中，任何改变了描述词的 apply 之后，**重新编码文本嵌入**——即它的 `make preprocess-te`。
   训练器的缓存会被原样复用，且从不自行过期，因此描述词已改而缓存仍旧时，训练用的是旧文本。
3. Resize 是共享的：只要档位一致，训练器的 `make preprocess-resize` 会发现每张图像已在其桶中并跳过它。

把两者指向同一个主目录（这里也尊重 `ANIMA_HOME`），就什么都不用移动。
从这里开始由训练器自己的指南接手——[Anima LoRA Guidebook][trainer-guide]。

[trainer-guide]: https://github.com/sorryhyun/anima_lora/blob/main/docs/guidelines/指南书.md

## 9. CLI 等价命令

每个阶段都是一个 `python -m` 模块，作用于 GUI 表单所填的同一个请求对象，
每个表单字段对应一个标志（`--help` 列出它们）。路径相对于整理主目录。
描述词阶段用下划线拼写标志（`--path_pattern`），分组和蒙版用连字符（`--source-dir`）；
两种拼写在任何地方都被接受。

| 阶段 | 模块 | 不带 `--apply` 时是否写入？ |
|---|---|---|
| Resize | `anime_tools.stages.cli.resize_images` | 总是写入 |
| Autotag | `anime_tools.stages.cli.autotag_captions` | 试运行 → `report.json` |
| Position | `anime_tools.stages.cli.position_captions` | 试运行 → `report.json` |
| Correct | `anime_tools.stages.cli.correct_captions` | 总是写入 |
| Audit | `anime_tools.stages.cli.audit_multiview` | 试运行 → `report.json` |
| OCR | `anime_tools.stages.cli.ocr_captions` | 试运行 → `report.json` |
| Groups | `anime_tools.grouping.cli.build_groups` | 总是写入 `groups.json` |
| Subject masks | `anime_tools.masking.cli.generate_masks` | 总是写入 |
| Text masks | `anime_tools.masking.cli.generate_masks_mit` | 总是写入 |
| Merge masks | `anime_tools.masking.cli.merge_masks` | 总是写入 |
| Export | `anime_tools.stages.cli.export_workspace` | 试运行 → `report.json` |

试运行的阶段把 `report.json` 写到 `workspace/captions/<stage>/` 下然后停止。`--apply` 真正写入。
`--from_report <report.json>` 在不加载模型的情况下重放一次试运行的提案，
跳过其间发生了变化的任何描述词，并在它读取的报告旁写 `apply_report.json`。
GUI 的 Undo 就是同一重放的倒放。

```bash
python -m anime_tools.stages.cli.autotag_captions --mode merge            # dry run
python -m anime_tools.stages.cli.autotag_captions --mode merge --apply    # write
python -m anime_tools.stages.cli.export_workspace --apply                 # publish
```

Python API 是同一个对象：[`examples/`](../../examples/README.md) 中每个功能有一个可运行的脚本，
API 与 CLI 并列。

## 11. 故障排除

**某个阶段因门控仓库错误失败（来自 Hub 的 401 / 403）。** Token 缺失，或该账户尚未接受该仓库的条款。
在 ⚙ Settings 中设置 Token，然后以同一账户登录，打开 Models & weights 中该行的 *accept the terms*
链接。Download 按钮能在不完整运行阶段的情况下复现该失败。

**`uv` 在我自己的项目中解析 numpy 失败。** SAM3 过时的 `numpy<2` 锁定。把 §3.2
的覆盖加到你的 `pyproject.toml` 中。

**macOS：`import sam3` 抱怨 triton，或张量无法放到 `cuda` 上。** 两者都在本包的 SAM3
加载器内部处理；如果你看到它们，说明你在自行导入 sam3，或在运行旧的 release。
SAM3 阶段在那里以 CPU 运行，很慢。

**Windows：torch 没有 CUDA。** PyPI 的 Windows torch 仅支持 CPU。
用默认使用 CUDA 索引的 PowerShell 安装程序重新安装，或显式设置 `TORCH_INDEX`。

**某个阶段看不到任何图像 / 对这张图像什么都不做。** 该图像不在 `workspace/resized/` 下。
要么它低于缩放下限（像素数量小标签会这样说；在 ⚙ Advanced settings › Preprocess 中调低下限），
要么 `src` 根目录没有指向你的数据集。

**"saved — .variants.txt is now stale"。** 你编辑了一条带有变体的修订描述词。
用相同的变体数量重新运行 Correct，然后运行训练器的 TE 重新编码。

**Undo 说它跳过了一些东西。** 描述词已不再是该次运行写下的内容——你或后来的运行改动了它——
因此那一行被放过了。被跳过的行仍在报告中。

**某次运行读取了错误的报告，或两个阶段共用一份。** 每个阶段在报告根目录下保有自己的目录
（`captions/autotag`、`captions/position`、…）；根目录是一个 Settings 值，移动它会把它们全部移动。
留空则报告放在 `dst` 根目录旁边。

**审计写了我的主描述词，我想把它找回来。** 工具不对 `image_dataset/` 做版本管理；
审计的 `report.json` 保存每次写入之前的文本，Undo 会重放它。
