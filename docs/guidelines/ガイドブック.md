# anime_tools ガイドブック

このドキュメントは **anime_tools** でデータセットをキュレーションするための、最初から最後までの手引きです。
インストール、画像の配置、Web GUI の起動、キャプション / グループ化 / マスクの各ステージの順番どおりの実行、
そして結果を [Anima LoRA トレーナー](https://github.com/sorryhyun/anima_lora) に渡すところまでを扱います。
ワンライン インストーラーでインストールし、コードを一度も開いたことのない方に向けて書かれています。
各ステージが何を読み、何を書き、実行をどう取り消すかを説明します。
ノブそのものは各ステージのフォーム上にあり（そのステージ自身の `--help` から生成されます）、
その説明は各セクションからリンクされている設計ドキュメントにあります。

## 1. anime_tools とは

`anime_tools` は Anima LoRA トレーナーのデータセット・キュレーション側の半分を、単体で動くように切り出したものです。
インストールは小さく、DiT も VAE も不要で、生成したデータセットはどのトレーナーにも渡せます。
手書きキャプション付きの画像フォルダを受け取り、トレーナーが学習前に読むすべて —
バケットリサイズ済み画像、補正・拡充されたキャプション、キャプションバリアント、型付きタグインデックス、
学習用マスク、重複を間引くためのグループ化マニフェスト — を生成します。

トレーナーはこのパッケージに依存しますが、このパッケージがトレーナーをインポートすることはありません。
両者が合意する事柄 — ファイル名、キャプション文法、成果物の置き場所 — はすべて
[`docs/contract.md`](../contract.md) に一度だけ書かれています。

## 2. 動作要件

| 項目 | 備考 |
|---|---|
| Python | **3.13**。インストーラーが固定します。マシンに無ければ `uv` が取得します。 |
| GPU | 任意ですが強く推奨します。すべてのモデルステージ（タガー、SAM3、PE-Spatial、テキストセグメンター、OCR）は CPU でも動きますが、速度は数分の一です。各ステージは torch が CUDA を認識すれば CUDA を、そうでなければ CPU を選びます。 |
| OS | Linux、Windows、macOS。macOS には CUDA も triton もありません。パッケージが SAM3 をその両方に対してシムするため、SAM3 ステージはそこでは CPU で動きます。 |
| ディスク | 各ステージが初回使用時に取得するモデル（タガーのバックボーン、SAM3、PE-Spatial、テキストネット、OCR、Danbooru タグ KB）に加え、`workspace/` 以下のデータセットのリサイズ済みコピー。 |

> **PyPI の Windows 向け torch は CPU 専用です。** そのため PowerShell インストーラーはデフォルトで
> CUDA 13.0 の torch インデックスを使います（§3）。PyPI の Linux 向け torch は最初から CUDA を同梱しています。

## 3. インストール

### 3.1 ワンライン、チェックアウト不要

Linux / macOS:

```bash
curl -fsSL https://github.com/sorryhyun/anime_tools/releases/latest/download/install.sh | sh
```

Windows (PowerShell):

```powershell
irm https://github.com/sorryhyun/anime_tools/releases/latest/download/install.ps1 | iex
```

どちらも [uv](https://astral.sh/uv) が無ければインストールしたうえで、最新リリースを torch と SAM3 込みで
専用の仮想環境に `uv tool install` し、`anime-tools-gui` を PATH に置きます。
git のチェックアウトも CUDA ツールキットも不要です。torch の wheel が CUDA ランタイムを同梱しています。

インストーラーは 2 つの環境変数で制御できます:

| 変数 | 効果 |
|---|---|
| `ANIME_TOOLS_VERSION=v0.3.1` | 最新リリースの代わりにそのタグをインストールします。 |
| `TORCH_INDEX=https://download.pytorch.org/whl/cu130` | torch 用の追加パッケージインデックス。PowerShell インストーラーはすでにこれをデフォルトにしています。Linux では CPU 専用ビルド（`…/whl/cpu`）にしたい場合にだけ必要です。 |

完了したら、PATH の変更が反映されるように**新しいシェル**を開いてから:

```bash
cd <your dataset folder>
anime-tools-gui --open
```

### 3.2 自分のプロジェクトの依存関係として

```bash
uv add "anime-tools @ git+https://github.com/sorryhyun/anime_tools"
```

PyPI パッケージはありません。タグを固定するか、`[tool.uv.sources]` をチェックアウトに向けてください。
自分の `pyproject.toml` にコピーしておくべきものが 1 つあります。
SAM3 は `numpy<2` を固定していますが、この固定は古くなっています。
このリポジトリはそれをオーバーライドしていますが、uv が `[tool.uv]` を尊重するのはワークスペースのルートだけなので、
anime-tools に*依存する*プロジェクトはオーバーライドを繰り返さないと numpy の解決に失敗します:

```toml
[tool.uv]
override-dependencies = ["numpy>=2.0"]
```

上のインストーラーは、同じオーバーライドをコマンドラインで渡しています。

### 3.3 ツールインストールから CLI を実行する

PATH 上にあるコマンドは `anime-tools-gui` だけです。
ターミナルからステージを実行するには、ツールの環境の中で Python を実行します:

```bash
uv tool run --from anime-tools python -m anime_tools.downloads --list
```

## 4. キュレーションホームとそのレイアウト

すべては 1 つのディレクトリ、**キュレーションホーム**からの相対です。優先順位の順に、`ANIME_TOOLS_HOME`、
次に `ANIMA_HOME`（トレーナー自身のホーム。トレーナーが使うツリーがそのまま使えます）、次に実行したディレクトリです。
`anime-tools-gui --home <dir>` はそのサーバーに対してこれを設定します。

```
<home>/
  image_dataset/                  INPUT  — your images + hand-written captions; the tools only read it
  workspace/                      everything the tools produce
    resized/<rel>.png               bucket-resized image — the tree every stage reads
    resized/<rel>.txt               the revised caption (stage output)
    resized/<rel>.history.txt       what that caption used to say, one line per version
    resized/<rel>.variants.txt      shuffle / dropout variants, v0 = pristine
    ocr/<rel>.ocr.txt               words in the picture (OCR); not a caption
    masks_sam/  masks_mit/          each mask generator's own tree
    masks/<rel>/{stem}_mask.png     the merge of the two — what Export publishes
    captions/<stage>/report.json    what each run did, and how to undo it
    groups/groups.json              the grouping manifest
  post_image_dataset/             OUTPUT — written only by Export; the tree the trainer reads
  models/                         model weights (ANIME_TOOLS_MODELS overrides)
```

目にするものの大半は、3 つのルールで説明できます:

- **`image_dataset/` はステージにとって読み取り専用です。** そこにあるあなたのキャプションが*マスター*です。
  すべてのステージは代わりに `workspace/resized/` 以下に*改訂版*キャプションを書き、
  改訂版がまだ無いときはマスターにフォールバックします。マスターを書くものは 2 つしかありません。
  GUI のキャプションエディターでその段を手で編集したときと、Export です。
- **画像を開くすべてのステージは `workspace/resized/` 以下の画像を開きます** — マスキングもグループ化も含めてです。
  そのためパイプライン全体が 1 つのジオメトリを共有します。`image_dataset/` にしか無い画像は、それらからは見えません。
  GUI がそれを必要とするステージの前に自動で Resize を実行するのはこのためです（§7.1）。
- **Export 以外は `workspace/` の外に何も書きません**（§7.9）。ワークスペースは削除して再生成できます。
  ステージによってマスターキャプションを失うことはありません。

画像ファイルはステムでキャプションと対応付けられます: `chars/alice/001.png` は `chars/alice/001.txt` を読みます。
サブフォルダはパイプライン全体を通してそのまま保たれます（上記の `<rel>`）。

> **ワークスペース導入前のインストールからのアップグレード**（`post_image_dataset/resized/` に直接書いていたもの）:
> `python -m anime_tools.workspace.migrate` は何を移動するかを表示し、`--apply` で実際に移動します。
> ディレクトリをリネームするだけで、マージは決して行いません。移動先がすでに存在すれば報告してスキップします。
> ⚙ Settings で古いパスに固定していたデータセットルートは名指しされますが書き換えられません —
> そこはご自身でクリアしてください。

## 5. Hugging Face サインインとモデル

モデルのうち 2 つは Hugging Face Hub 上で**ゲーテッド**です。
dbv4 タガーのバックボーン（GPL-3.0。決して同梱せず、ロード時に*あなたの*トークンで取得します）と SAM 3 です。
どちらも read 権限のトークンが必要で、そのトークンのアカウントは各リポジトリの利用規約に一度同意している必要があります。

GUI では: ☰ → **⚙ Settings…** → *Hugging Face* → トークンを貼り付けます。
トークンは `huggingface_hub` のログインに渡されてそこに保存され、二度と表示されません。
設定されるまでヘッダーには **⚠ no HF token** と表示されます。
Models リストのゲーテッド行には *accept the terms* リンクがあります。
同じアカウントでサインインした状態で開いてください。

事前に取得しておく必要はありません。**すべてのステージは必要なものを初回使用時に取得します。**
**Models & weights** ダイアログ（☰ → *Models & weights*）はチェックポイントごとに 1 行 —
用途、インストール済みかどうか、置き場所 — を一覧し、行ごとの **Download** ボタンと
**Download all N missing** を備えています。
ダウンロードは通常のジョブとして一度に 1 つずつ実行され、ステージとスロットを共有します。
これらのボタンは、待ち時間と、ゲーテッドリポジトリによる拒否があればそれを、あなたが選んだ瞬間に移すだけです。

ターミナルからは:

```bash
python -m anime_tools.downloads --list        # every row: installed / MISSING, repo, destination
python -m anime_tools.downloads               # fetch every missing one
python -m anime_tools.downloads sam3 tagger   # fetch by id
```

重みは `<home>/models/` 以下に置かれます（`ANIME_TOOLS_MODELS` で上書き可能）。
例外は SAM3 の被写体ソフトプロンプトで、トレーナーがそこに置いているため `networks/calibration/` にあります。

## 6. GUI

```bash
anime-tools-gui --open              # http://127.0.0.1:8790, opens the browser
anime-tools-gui --home ~/datasets/x # a different curation home
anime-tools-gui --host 0.0.0.0      # expose on the LAN (a headless GPU box)
```

ポートが使用中なら次の空きポートが使われ、表示されます。`--host 0.0.0.0` には**認証がありません** —
前段に自前のトンネルを置いてください。サーバー自体はモデルを一切ロードしません。
すべてのステージは `python -m …` サブプロセスとして一度に 1 つずつ実行され、その出力がパネルにストリーミングされます。

### 6.1 サイドバーはデータセットそのもの

`image_dataset/` 以下のすべての画像がフォルダ構成のまま並び、行のドットで何が存在するかを示します:
リサイズ済み、マスクあり、そしてキャプションの段ごとに 1 つのドットです。
各画像の下では、そのキャプションが古いものから順に**ラダー**を成します:

| 段 | ファイル | 編集可 |
|---|---|---|
| **master** | `image_dataset/<rel>.txt` — 手書き。ステージは読むだけです | はい |
| **history** (`revised@1`, `revised@2`, …) | `<rel>.history.txt` — 改訂版キャプションを置き換えた各実行の前に、それが何と言っていたか | いいえ |
| **revised** | `workspace/resized/<rel>.txt` — ステージの出力。次の実行がこれを書き換え、このテキストをバージョンとして残します | はい |
| **variants** (`v0`, `v1`, …) | `<rel>.variants.txt` — 生成物。`v0` は手つかずの改訂版キャプションです | いいえ |

**filter** ボックスでツリーを絞り込めます。`↑`/`↓` または `j`/`k` で画像を移動し、
URL の `#<rel>|<kind>` は 1 つのキャプションへのリンクです。**tree / groups** トグルは同じ一覧を
2 つの順序 — フォルダ順、または Groups ステージが見つけた近縁（near-twin）グループ順（§7.7）— で描きます。

### 6.2 キャプションエディター

画像を選択すると、その画像（ソース / マスク / オーバーレイ）がキャプションの横に表示されます。
エディターは 1 つで、バージョンごとにバッジが付きます。タグバッグと各位置節はテキスト内でボックスに囲まれます。
ボックスはサーバー自身のパーサーに由来するため、ブラウザがキャプションの構造を推測することはありません。
タグをダブルクリックすると Danbooru タグ KB で調べられます（ダウンロード後）。

**Save**（⌘/Ctrl+Enter）は `master` または `revised` を書き込みます。他の段は読み取り専用です。
すべての書き込みは、手動でもステージでも同様に、置き換えたテキストを history の段に積みます。
保存すると次に何をすべきかが表示されます。トレーナーのテキストエンコーダー再エンコードは常に、
そしてすでに `.variants.txt` があった改訂版キャプションを編集した場合は *Correct の再実行*も —
そのサイドカーが古くなっているためです。

キャプションの下には、OCR ステージが読んだ画像であれば**画像内のテキスト**が、
各行の信頼度と位置とともに表示されます（§7.6）。

### 6.3 ドックはステージランナー

下端のボタン列が**ステージ一覧そのもの**です。Resize は舞台裏にあり、ボタンは
**Autotag · Curate · OCR · Groups · Masks · Export** です。
Curate は 3 つのステージ（Position / Correct / Audit）を、Masks も 3 つ（Subject / Text / Merge）を抱えており、
パネル内で選びます。1 回クリックするとステージのフォームが開き、開いているものをもう一度クリックするとドックが折りたたまれます。

フォームはステージ自身の `--help` から生成されます。開いたときに見えるのは実行ごとに変えたくなるノブで、
残りは各グループの末尾の **▸ advanced (n)** に折りたたまれ、隠れたフィールドがデフォルトから外れていれば注記が付きます。
データセットルート、レポートルート、モデルパスがフォームに現れることはありません — それらは ⚙ Settings から来ます。

- **Run** は選択中の画像だけを対象にステージを実行します（**just `<rel>`**）。
- **Run batch** は Settings の `path_pattern` が指すすべての画像に対して実行します — `*` はデータセット全体です。
- **Undo** はこのステージの直前の実行が書いたものを、そのレポートを逆再生して元に戻します。
- **Cancel** は実行中のジョブを停止します。

パネルを日本語にすると、これらのボタンは **実行 / 一括実行 / 元に戻す / 中止**、☰ メニューの項目は
**⚙ 設定… / モデルと重み / 言語** と表示されます。本書では英語名をそのまま使います。

**Run は実際に書き込みます。** GUI には Apply ゲートがありません。
実行が置き換えたものはキャプションのバージョンバッジ（`revised@2`）になり、
実行のレポートはキャプションパネルで画像ごとの差分として読み返され、
Undo はそのレポートを 2 つのテキストを入れ替えて再生したものです。
Undo にはガードがあります。実行後に手で編集したキャプションはそのまま残され、スキップとして数えられます。

最新の出力行はステージバーに表示され、**log** ボタンで全体を開けます。
画像を走査するステージはプログレスバーを表示し、前にプリフライトが付く実行は先に *step 1/2 · resize* を表示します。

### 6.4 ⚙ Settings は 3 つのダイアログ

| ダイアログ | 内容 |
|---|---|
| **Settings** | キュレーションホームとモデルディレクトリ、5 つの**データセットルート**（`src`、`master`、`dst`、`masks`、`out`）、Hugging Face トークン。 |
| **Advanced settings** | それを受け取るすべてのステージに埋め込まれる**ステージデフォルト**（`path_pattern`、タガーディレクトリ、SAM3 チェックポイントとソフトプロンプト、レポートルート、マスクルート）と、**Preprocess** ブロック — Resize にはドックボタンが無いため、Resize ステージ自身のフォームです。 |
| **Models & weights** | §5 のモデル行。 |

各ダイアログは自分が持つものだけを保存します。ルートはキュレーションホームからの相対で、存在しないものはフラグが立ちます。
パネルは保存された設定が指すどのルートも*読める*一方、ディレクトリを*作る*のはホーム以下に限られるため、
外部ルートのタイプミスは新しい空ディレクトリではなく、存在しないルートになります。

☰ メニューの **Language** 行はパネルを英語・韓国語・日本語・中国語の間でその場で切り替えます。
初回訪問時はブラウザ自身の言語リストに従います。翻訳されるのはパネルのクローム部分だけです —
ステージのタイトル、フォームのラベルとヘルプはその `--help` から来るため英語のままで、
キャプション、タグ、パスはデータです。

## 7. ステージごとのワークフロー

上から順に実行してください。各ステージはリサイズ済みツリーを読むため、画像が Resize を通るのは一度だけで、
各キャプションステージは前のステージが書いた改訂版キャプションを読みます。

### 7.1 Resize（自動）

**読み込み** `image_dataset/`。**書き込み** `workspace/resized/<rel>.png`。

各画像は、最も小さいリサイズで済むバケット階層に、その階層のトークン帯の中で元のアスペクト比を保ったまま収まります。
ジオメトリはトレーナー自身のものなので、どちらの側が先にリサイズしても、
もう一方はすべての画像がすでにバケットにあると判断してスキップします。
ピクセル下限（デフォルト 0.5 MP）未満の画像はレポートで**スキップされ、名前が挙げられます** —
そのような画像は決してリサイズされないため、どのステージからも見えません。
画像パネルのピクセル数チップにその旨が表示され、下限は ⚙ Advanced settings › Preprocess にあります。

これをクリックすることはありません。GUI はリサイズ済みツリーを読むすべてのステージの最初のステップとしてこれを実行し、
1 枚の画像に対する実行はその画像だけをリサイズします。すでに最新の画像はスキップされるため、プリフライトのコストはほぼゼロです。
常に書き込みます。ドライランはありません。

> 階層（`target_res`）はトレーナーのものと一致していなければなりません。
> さもないと双方が互いの出力をリサイズし続けます。

### 7.2 Autotag captions（キャプションの自動タグ付け）

**読み込み** リサイズ済みの各画像とそのキャプション（改訂版、無ければマスター）。**書き込み** 改訂版キャプション。
**モデル**: Anima Tagger（タガーチェックポイント + ゲーテッドの dbv4 バックボーン）。

画像ごとに Anima 順のタグ文字列 — `rating, count, characters, copyrights, @artists,
generals` — を予測します。3 つのモードがあります:

| モード | 動作 |
|---|---|
| `missing`（デフォルト） | **どのキャプションも語っていない**画像だけ。既存のものには触れません。 |
| `merge` | キャプションに無いタグを追記し、位置節は保ちます。 |
| `overwrite` | キャプションを丸ごと置き換えます。古いテキストは history バージョンとして残ります。 |

非破壊なのは `missing` だけです。他の 2 つは history の段と Undo で元に戻せます。
出力はあくまで出発点として扱ってください — 学習前に名前、シリーズ、アーティストを確認してください。
タガー自体については [`docs/anima_tagger.md`](../anima_tagger.md) を参照してください。

### 7.3 Correct + mirror captions（キャプションの補正とミラー）

**読み込み** マスターキャプションと Danbooru タグ KB。**書き込み** 改訂版キャプションと、任意で `.variants.txt`。

各マスターを補正済みの改訂版キャプションにミラーします。タグは KB に照らして型付けされ Anima のバケットに並べ替えられ、
任意のトリガーワードが差し込まれ、任意の `@no-artist` センチネルが付き、
任意の**ドロップグループ**がマスターに触れずにミラーされた全キャプションからタグファミリーごと取り除きます。
バリアント数を設定すると `<rel>.variants.txt` も書きます。`v0` は補正済みキャプション、
`v1…` はスマートシャッフルとドロップアウトの抽選で、トレーナーはこれをそのままエンコードします。

常に書き込みます。ドライランもレポートも無いため Undo もありません — 置き換えられたテキストは history の段にあります。
KB は Models の **Danbooru tag KB** 行です（§5）。任意の English 行は、タグ検索が表示する説明文を書き換えます。

> Correct がミラーするのは**マスター**です。改訂版キャプションの位置節は再実行しても生き残りますが
> （新しいミラーに再付加されます）、Autotag `merge` がフラットバッグに追加したタグは生き残りません。
> そのため Correct は Autotag `merge` の後ではなく前に実行してください。

### 7.4 Position captions（位置キャプション）

**読み込み** リサイズ済み画像とそのキャプション。**書き込み** 改訂版キャプション。
**モデル**: SAM 3（ゲーテッド）、被写体ソフトプロンプト、Anima Tagger。

被写体が 2 つ以上ある画像について、それぞれを検出し、読み順に並べ、マスクで空白化した各クロップにタグ付けし、
キャプションを位置節文法 `<flat tag bag>. On the left, …. On the right, ….` に書き換えます。
1 つの被写体に属するタグはフラットバッグからその被写体の節へ*移動*します。
キュレーション済みキャプションが一度も言っていないことは、わずかな許容量を超えて作り出されることはありません。
被写体が 1 つの画像はスキップされ、レポートに理由が記されます。

適用は、書き換えたキャプションの横にある古い `.variants.txt` を削除します。
**取り消し**は専用のモード `--flatten` で、モデルをロードせずにすべての節をフラットバッグに戻します — または Undo です。
完全な文法、ゲート、すべてのノブは [`docs/position_captions.md`](../position_captions.md) にあります。

### 7.5 Multiview audit（マルチビュー監査）

**読み込み** Position ステージがスキップした単一被写体の画像。**書き込み** **マスターキャプション**への
`multiple views`、そしてそれだけ。**モデル**: Position と同じ。

実際には 1 人の少女の複数ビューである `1girl` 画像を見つけ、
それぞれをレポートディレクトリ以下のコンタクトシートとともに報告します。
適用はデフォルトで強い所見に限定されます。弱い所見の裏付けはジオメトリだけなので、まずシートを確認してください。

> これは `image_dataset/` を直接書く唯一のステージです。レポートはすべての書き込みの変更前テキストを保持し、
> Undo はそれを読み戻します。[`docs/multiview_audit.md`](../multiview_audit.md) を参照してください。

### 7.6 OCR text（画像内テキストの OCR）

**読み込み** リサイズ済み画像。**書き込み** `workspace/ocr/<rel>.ocr.txt`。
**モデル**: PP-OCRv6 検出 + 認識（英語、中国語、日本語。ハングルは非対応）。

*画像の中にある*言葉 — セリフ、看板、効果音 — を、信頼度と位置とともに 1 行ずつ記録します。
これは**キャプションではありません**。下流の何もこれをエンコードせず、キャプションの読み書きは無く、
後で再エンコードも不要です。画像パネルに各行が表示されます。
デフォルトでは ASCII のみの行（ページ番号、URL）は捨てられ、縦書きの日本語の列は吹き出しごとに 1 行に結合されます。

### 7.7 Build groups（グループの構築）

**読み込み** リサイズ済み画像。**書き込み** `workspace/groups/groups.json`。**モデル**: PE-Spatial。

ほぼ同一の画像 — 重複、別バージョン、1 枚の絵のクロップ — を、ファイル名やキャプションではなく視覚的なコンテンツで、
最上位フォルダ単位でクラスタリングします。サイドバーの **groups** 順序がその結果を描きます。
グループごとに折りたたみ可能なヘッダーが 1 つあり、冗長なものが一か所に集まるので間引きが容易です。
フィルターと保留中のドットは、どちらの順序でも同じ意味です。

再実行のコストは低く、特徴量は `~/.cache/near_twin/` 以下（`NEAR_TWIN_CACHE` で上書き可能）に
ファイルのサイズと mtime のスタンプ付きでキャッシュされるため、再リサイズしても変わった画像だけが正確に再計算されます。
クラスタリングの厳しさはフォームの 2 つのマッチしきい値で調整します。[`docs/grouping.md`](../grouping.md) を参照してください。

### 7.8 Masks: Subject, Text, Merge（マスク: 被写体・テキスト・マージ）

**読み込み** リサイズ済み画像。**書き込み** `workspace/masks_sam/`、`workspace/masks_mit/`、
そして両者のマージを `workspace/masks/` 以下に — ソースのサブフォルダを写した 8 ビットの `{stem}_mask.png` です。
**モデル**: 両ジェネレーターとも SAM 3。Text にはさらに漫画テキストセグメンターと ComicTextDetector ゲート。

- **Subject** は被写体を残して背景をマスクアウトします。
  デフォルトでは学習済みの被写体プロンプトで SAM3 をグラウンディングします。
  マスク*アウト*するプロンプト（`speech bubble,text`）を追加できます。
- **Text** は文字と吹き出しを 2 つの検出器でマスクします。それぞれ独自のスイッチの裏にあり —
  プロンプトによる SAM3（吹き出しは形）と UNet++ セグメンター（文字はストローク）— 1 回の膨張の前に和集合を取ります。
  両方オフは、このステージが拒否する唯一のフォームです。
- **Merge** は 2 つのツリーのピクセルごとの最小値を `workspace/masks/` に取ります。
  サイドバーが *mask* / *overlay* として表示し、Export が公開するツリーです。
  存在しない入力ツリーはスキップされるため、ジェネレーターを 1 つだけ実行しても有効な片割れです。

3 つのディレクトリは 3 つのフィールドではなく 1 つの設定です。
両ジェネレーターはマスクに同じ名前を付けるため、共有ツリーでは互いに上書きしてしまうからです。
マスクは常に書き込みます。変更するには再生成してください。[`docs/masking.md`](../masking.md) を参照してください。

### 7.9 Export workspace（ワークスペースのエクスポート）

**読み込み** ワークスペース。**書き込み** `post_image_dataset/` — そして、改訂されたマスターがあれば
`image_dataset/`。

ワークスペースの外に書く唯一のステージです。6 種類の成果物 — リサイズ済み画像、改訂版キャプション、
バリアントサイドカー、マスク、改訂されたマスター、キャプションインデックス — を公開し、
それぞれを移動先と個別に照らして判断します。
同一のファイルはスキップされる（テキストはバイト比較、ピクセルはサイズと mtime）ため、
変更のないデータセットの再エクスポートは走査と stat が 1 回ずつで済みます。
常に**コピー**し、リンクは決して作らないため、ワークスペースを消してもエクスポートツリーは残ります。

CLI からはデフォルトでドライランになり、コピーする予定のものを一覧します。GUI では **Run** がコピーし、
**Undo** はエクスポート自身の台帳から上書きしたテキストを復元します。
上書きされた*ピクセル*は復元できず、その旨が報告されます。トレーナーは Export が書いたものだけを読みます —
すべてのパスは [`docs/contract.md`](../contract.md) §2 を参照してください。

## 8. トレーナーへの引き渡し

1. **Export**（§7.9）。トレーナーは画像と改訂版キャプションを `post_image_dataset/resized/` から、
   マスクを `post_image_dataset/masks/` から、マスターを `image_dataset/` から読みます。
2. トレーナー側で、キャプションを変更した適用の後は必ず**テキスト埋め込みを再エンコード**します —
   トレーナーの `make preprocess-te` です。トレーナーのキャッシュはそのまま再利用され、自動で期限切れになることは無いため、
   キャッシュが古いままの変更済みキャプションは古いテキストで学習してしまいます。
3. Resize は共有です。階層が一致していれば、トレーナーの `make preprocess-resize` は
   すべての画像がすでにバケットにあると判断してスキップします。

両方を同じホームに向ければ（ここでは `ANIMA_HOME` が尊重されます）、何も移動しません。
そこから先はトレーナー自身のガイド — [Anima LoRA ガイドブック][trainer-guide] — に引き継ぎます。

[trainer-guide]: https://github.com/sorryhyun/anima_lora/blob/main/docs/guidelines/ガイドブック.md

## 9. CLI での同等コマンド

すべてのステージは、GUI のフォームが埋めるのと同じリクエストオブジェクトの上に載った `python -m` モジュールで、
フォームのフィールド 1 つにつきフラグが 1 つあります（`--help` で一覧できます）。パスはキュレーションホームからの相対です。
キャプションステージはフラグをアンダースコアで（`--path_pattern`）、グループ化とマスキングはハイフンで
（`--source-dir`）綴りますが、どちらの綴りもすべての場所で受け付けられます。

| ステージ | モジュール | `--apply` 無しで書き込む? |
|---|---|---|
| Resize | `anime_tools.stages.cli.resize_images` | 常に書き込む |
| Autotag | `anime_tools.stages.cli.autotag_captions` | ドライラン → `report.json` |
| Position | `anime_tools.stages.cli.position_captions` | ドライラン → `report.json` |
| Correct | `anime_tools.stages.cli.correct_captions` | 常に書き込む |
| Audit | `anime_tools.stages.cli.audit_multiview` | ドライラン → `report.json` |
| OCR | `anime_tools.stages.cli.ocr_captions` | ドライラン → `report.json` |
| Groups | `anime_tools.grouping.cli.build_groups` | 常に `groups.json` を書き込む |
| Subject masks | `anime_tools.masking.cli.generate_masks` | 常に書き込む |
| Text masks | `anime_tools.masking.cli.generate_masks_mit` | 常に書き込む |
| Merge masks | `anime_tools.masking.cli.merge_masks` | 常に書き込む |
| Export | `anime_tools.stages.cli.export_workspace` | ドライラン → `report.json` |

ドライランのステージは `workspace/captions/<stage>/` 以下に `report.json` を書いて停止します。
`--apply` で実際に書き込みます。`--from_report <report.json>` はドライランの提案をモデルをロードせずに再生し、
その間に変更されたキャプションはスキップして、読んだレポートの横に `apply_report.json` を書きます。
GUI の Undo は同じ再生を逆向きにしたものです。

```bash
python -m anime_tools.stages.cli.autotag_captions --mode merge            # dry run
python -m anime_tools.stages.cli.autotag_captions --mode merge --apply    # write
python -m anime_tools.stages.cli.export_workspace --apply                 # publish
```

Python API も同じオブジェクトです。[`examples/`](../../examples/README.md) には機能ごとに実行可能なスクリプトが
1 つずつあり、CLI と並べて API を示しています。

uv tool upgrade anime-tools          # tool install

## 11. トラブルシューティング

**ステージがゲーテッドリポジトリのエラー（Hub からの 401 / 403）で失敗する。**
トークンが無いか、アカウントがそのリポジトリの利用規約に同意していません。⚙ Settings でトークンを設定してから、
Models & weights の該当行の *accept the terms* リンクを、同じアカウントでサインインした状態で開いてください。
Download ボタンはステージをフル実行せずにこの失敗を再現できます。

**自分のプロジェクトで `uv` が numpy の解決に失敗する。** SAM3 の古い `numpy<2` 固定が原因です。
§3.2 のオーバーライドを `pyproject.toml` に追加してください。

**macOS: `import sam3` が triton について文句を言う、またはテンソルを `cuda` に置けない。**
どちらもパッケージの SAM3 ローダー内で処理されています。
これらが見えるなら、sam3 を自分でインポートしているか、古いリリースを実行しています。
SAM3 ステージはそこでは CPU で、ゆっくりと動きます。

**Windows: torch に CUDA が無い。** PyPI の Windows 向け torch は CPU 専用です。
CUDA インデックスをデフォルトとする PowerShell インストーラーで再インストールするか、`TORCH_INDEX` を明示的に設定してください。

**ステージが画像を見つけない / この画像に対して何もしない。** その画像が `workspace/resized/` 以下にありません。
リサイズの下限未満か（ピクセル数チップにそう表示されます。⚙ Advanced settings › Preprocess で下限を下げてください）、
`src` ルートがデータセットを指していないかのどちらかです。

**「saved — .variants.txt is now stale」。** バリアントを持つ改訂版キャプションを編集しました。
同じバリアント数で Correct を再実行し、その後トレーナーの TE 再エンコードを行ってください。

**Undo が何かをスキップしたと言う。** キャプションが実行の書いた内容をもう保持していない —
あなたか後の実行がそれを変更した — ため、その行はそのまま残されました。スキップされた行はレポートにまだ残っています。

**実行が間違ったレポートを読む、または 2 つのステージが 1 つのレポートを共有する。**
各ステージはレポートルート以下に自分のディレクトリ（`captions/autotag`、`captions/position`、…）を持ちます。
ルートは 1 つの Settings 値で、それを動かせばすべてが動きます。空のままにするとレポートは `dst` ルートの横に置かれます。

**監査がマスターを書いてしまったので戻したい。** `image_dataset/` はツールによってバージョン管理されていません。
監査の `report.json` はすべての書き込みの変更前テキストを保持しており、Undo がそれを再生します。
